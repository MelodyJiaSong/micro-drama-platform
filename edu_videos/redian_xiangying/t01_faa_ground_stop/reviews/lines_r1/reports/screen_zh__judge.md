- P2 1 理由：b 站得住。l15 h2「多个航路管制中心出现通信问题 / 技术人员正在调查」与 l15 口播逐字相同，下面又印英文原文；l51「铜线拔了，换成光纤 / 数据架构还是 50 年前那一套」同样是口播加英文原话；l83 body「要换，就把「换」当成最该小心的事」照搬口播，片尾从严；l24「接下来的内容，不靠这次的结论」也是口播原句。a 自己在问题表里把 l15、l51、l83 标为 P2「必改」，却给 2 分，前后矛盾。a 的证据中，l07「有争议」不能算新说法：系列 README §3 要求标明说法性质，claims C31 的状态就是「有争议」，这个角标是规定动作。l15 的「「多个」还是「全部」中心」成立：这是口播没讲过的具体争议内容（C10）。
- P3 1 理由：给 1 分，但主因和 b 不同。开场 l02/l03（从严）截图上，28px 等宽英文六行占了卡片左侧约 2/3，中文要点「全部机场停飞」「特殊情况，出于安全」只有 38px，缩在右边，观众第一眼落在英文上；l03 只停 2.8s。另外 l08–l09 的「我们的判断」角标压在达菲、CBS 两条说法上（见补充）。b 的证据只部分成立：l32、l71 截图证实旧文字淡化后仍可读，材料清单漏列，这影响 P1 计数；但淡化和当前加粗的层级本身清楚，不构成层级失败。a 提的 s5 章名不一致不成立：屏上章节卡、页眉「05 · 反方怎么说」和 package.json chapters 都是「反方怎么说」；「反方最有力的说法」只出现在讲稿和 timeline.json 的内部标题里，观众看不到。

## 驳回
- a l07（P2 建议「删「有争议」」）：系列 README §3 要求在片中标明说法性质，C31 状态为「有争议」，角标不能删；能删的只有出处里重复的「计数口径不一」。
- b l15（改写「撤下…争议注释」）：理由同上，C10 状态为「有争议」，角标保留。只撤「「多个」还是「全部」」这段口播没讲过的细节，改为单独的「有争议」角标。
- a c_c5 / s5（P3 存疑「章名不一致」）：屏上章节卡、页眉、package.json 目录统一都是「反方怎么说」，「反方最有力的说法」只是讲稿内部标题，观众看不到，不构成屏幕不一致。
- a l68–l69（P4 改写「升级有风险 → 更不敢动」）：反方的意思是「你们老强调风险，让人更不敢动」，原文的重点在「说」。改成「升级有风险」等于替我方立论，意思反了。应改「强调风险 → 更不敢动」（8 字）。
- b l82（改写「离不开的系统／改动时，最危险」）：丢掉了「不是它老了」这层对比，而这层对比正是全片一句话论点（script.md 第 3 行），也是「太老 vs 更新」主线的落点，改了更差。h1 13 字超过 12 字的问题成立，应改为 h2「离不开的系统」／h1「不怕它老，最怕你动它」（9 字），保留对比，也和 package.json quote「最怕你动它」一致。
- b l54（改写「删除「一直撑着」」）：「一直撑着」是 l54 新出的唯一信息，对应口播「还得一直撑着」，删了这一屏就没有新内容了。要压图内字数，应把「2026 年 8 月」并入时间轴刻度（2026 已有），或把「下一代电信网」缩为「新网」。
