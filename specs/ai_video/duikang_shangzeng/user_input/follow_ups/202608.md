## 003 — 2026-08-29 16:30:00 — 对象建立改为「图先行」三步流程

> severity: high

### 指令

核心 object 的建立顺序**反转**：不是「先白模 → 白模图当结构参考 → 再出写实图」，
而是**图先行**——

- **Step 1**：纯文字 prompt、**不挂任何 reference**，尽量生成一张最好的整车全景基准图。
  这张图是后续一切的唯一锚点。
- **Step 2**：把 Step 1 的图挂进 reference 位，派生出各角度图（侧面 / 正面 / 背面 …）。
  每张派生图都挂**同一张**基准图，不是链式派生。
- **Step 3**：同样以这些图为输入，**由图生成 Blender 白模**（image-to-3D）。
  白模是图的下游产物，不是它的前置。

### 派生角度与对象拆分（本轮确认的四个决策）

1. **基准图角度** = 四分之三前侧 · 棚拍完整车身（同时读得到车头黑条、侧面竖开口、
   肩线、轮拱、座舱轮廓——F80 五个识别特征在这一视角全部可见）。
2. **派生角度补齐到 6 个**（front / side / rear3q / rear / top / low3q），
   覆盖全片 61 镜的机位需求，而非只做侧/正/背三个。
3. **Step 3 走 Blender MCP**（`generate_hyper3d_model_via_images`），
   由用户开着 Blender + addon，Claude 通过 MCP 跑。
4. **车内座舱是独立的第二个 object**（`f80_cockpit`），走同样的三步逻辑：
   基准图 = 驾驶位主视角，派生 3 个（`wheel` 仪表 / `paddle` 换挡拨片 / `console` 起动旋钮）。
   理由：车外靠剪影与比例识别，车内靠部件相对位置识别，混在一个对象里两边都锁不住。

### 一句话总结

对象建立顺序反转为「纯文字基准图 → 挂基准图派生 6 角度 → 由图生白模」；
车内座舱升格为独立的第二个对象，走同一套三步逻辑。

### 研究结论（改变了既有做法）

  「上传一次建立对象、此后每镜只带一张」作废，改为**参考包每镜随附**。
- **单次 50 个全模态参考：30 图 + 10 视频 + 10 音频。** 槽位稀缺的前提消失。
- **白模 clay render 是官方支持的参考模态**，明确用于指定 spatial structure /
  motion paths / **camera angles**。previz 不是变通，是正规通道。
- **提示词必须交代每个参考各管什么**（「哪个决定主体、哪个定下地点、哪个锁住色板」）
  —— 印证了 rule 4d §B 的 `参考用法:` 行。
- 官方自陈弱区：复杂运动的物理合理性、**多主体互动场景的稳定性**。

### 决策

- 场景**不建 object**：场景无界，没有「全部」可拍，指望参考图自己转方向＝每镜重新编造。
- 场景走**四层**：S1 高空俯视平面图（空间契约·从 blend 渲）→ S2 每地点广角全景（长相）
  → S3 方位板（构图）→ S4 逐镜 previz（机位·走位·时刻，权限最高）。
- **方位板数量由分镜表推导**：37 镜 → 12 张（不是每地点固定 4 方位的 16 张）。
- S1 从已有 `entropy_city.blend` 正交俯视**渲染**，不生成——与 previz 同坐标系、零漂移。

### 实测发现

平面图一渲出来就暴露：`entropy_city.blend` 的「城市」其实只有一个广场 + 一条街
（5 塔 + 20 个商铺盒），而 shot01（无人机穿梭城市上空）与 shot52（俯瞰全城复原）
都是 hero 镜，从空中只会读成一条布景街。已补 266 个体块城市肌理，
keep-out 让开广场/主街/桥面/隧道走廊，既有 61 份 previz 构图零影响。
**建模阶段必跑一次平面图渲染肉眼过一遍**——已升为 rule 4e 的强制步骤。

### 一句话总结

场景不建 object，走「平面图→广角全景→方位板→previz」四层；方位板数由分镜表推导（12 张）；

## 009 — 2026-08-30 — 场景层级模型：World / Place / Look 三种切法

> target_stage: 2
> target_artifacts:
>   - .claude/agent_refs/project/ai_video.md
>   - ai_videos/duikang_shangzeng/2_世界观人设/scenes/entropy_city/
> severity: high

### 指令

scene / Blender / Seedance 主体可能是不同层级：Blender 也许最外层一个完整 3D 世界就够，
但 Seedance 主体要体现光影特效细节，需要更细的划分；同一场地被摧毁、光影变化都会产生新主体。
要一套 generic 的层级策略 + **建立层级的 principle**，让以后所有剧的 scene 都能复用。

### 核心认识

三者被**三种不同的不变量**切开，不是一棵树的上下级：
Blender ＝ 空间连续性（只承载几何）｜主体 ＝ 外观不变量｜scene 卡 ＝ 叙事地点。
证据是那个不对称：**光影变 → 新主体但 Blender 不动；炸毁 → 新主体且 Blender 要变。**

四层：L0 世界观风格（文字，被继承）→ L1 World（.blend）→ L2 Place（scene 卡）
→ L3 Look ＝ **主体 ＝ Place × State**。主体 description ＝ 继承链拼出。

### 三条判定（本轮拍板）

1. **新主体判定＝调色师测试**：能后期调回来的差异（曝光/色温/对比）＝同主体；
   调不回来的（几何变/材质变/光的方向或性质变/增删物体）＝新主体。
2. **Blender 几何变体判定＝挡镜头测试**：「这个变化会不会让相机或主体走不了原路？」
   会 → 建 state collection；不会（焚黑/碎玻璃/积灰）→ 不建，交给主体材质层。
3. **建主体时机＝用到才建，但不允许建一半**：某 Place×State 第一次被镜头用到才建，
   一建就按固定视图集建完整。分工：*视图集规格*场景无关（不可读剧本）；*有哪些状态*是故事事实（可读剧本）。

### State 维度：封闭枚举 + 自由扩展位

`时间 日/夜/黄昏/黎明 · 天气 晴/雨/雪/雾 · 完损 完好/受损/废墟 · 季节 春/夏/秋/冬`
＋ `剧情态 <自由文本>`。状态是**相对基线的稀疏差量**；基线主体视图键不带状态标，
变体带 ≤2 字状态短标。**变体主体继承基线的平面图。**

### 反模式（明确禁止）

- 为了「更多细节/光影/特效」而拆更细的主体 —— 细节靠**给主体加视图**，不靠拆主体。
  拆碎会撞 1–8 主体上限，且一个地方失去唯一权威主体。
- 把「sub-scene」当独立层级 —— 商铺内景该独立是因为外观不变量断了，L2 地点切法已覆盖；
  目录嵌套是导航方便，不是语义层级。

### 一句话总结

确立 L0 风格 / L1 World / L2 Place / L3 Look(=Place×State) 四层模型与三条判定
（调色师测试 / 挡镜头测试 / 懒建但不建一半），State 用封闭枚举加自由扩展位。
