## 文件以外的完整 setting

两 run 的冻结输入对象相同，`input_hash` 都是 `a4d03e7d8c0b2f46e726b8fcfe0963bf33656dd20baf928e8354d4a5eb775b6f`。

- 六问 `frame`：原创人类少年米洛，艾泽拉斯原住民；争取第一次有报酬的跑腿差事，想获得下一次工作的机会；暂设经典旧世普通白天、北郡修道院附近虚构交接地点；目标→行动→阻碍→选择→代价及结果。
- `brief`：约 800–1400 中文字、小说式正文、温暖但有实际冲突、可有轻微人物幽默；不写摄影、Prompt、等级 UI 或突然觉醒。
- `assumptions`：上述主角与场景、篇幅和基调属于当轮暂定选择，不是用户确认的长期世界事实；原记录保留假设理由。
- `prior_accepted_state`：空列表，没有此前已确定集的状态输入。
- `independence`：排除旧候选、旧决策、旧代理会话、当前工作区草稿和未来集。
- `criteria`：动机可理解、事件有因果、人物或处境有变化、具体吸引力、只使用显式背景且标注虚构、保持最小 POC。
- `user_requests`：当次用户对故事生成、真实协作日志、六问、共享配置、只读 UI 和导航的要求；按 run 分别留存，不全等同于作者收到的指令。
- run2 另有 `comparison_plan`：同冻结输入/规则的独立复跑；作者不看 run1，不以制造差异为目标；两样本不能证明某一规则的因果影响。

`baseline-v1` 是事后从 run1 冻结输入建立的共享基线，run2 创建时沿用 run1 冻结输入。`workflow-v2` 和 `previous_configuration.json` 虽被文件清单登记，不能当作这两次生成实际采用的输入。JSON 文件字节的 SHA256 与规范化输入对象的 `input_hash` 是不同指纹，不要求相同。

## 各参与者实际看到什么

1. 主编组织冻结输入、派发作者/审稿、逐项取舍及修订。完整指令与回复保存在 `run.json#/participants`。
2. 独立作者读取本 run 的 `input.json`，收到完整作者任务；其中还有避免旧救援/师徒套路、只写文学故事、标注虚构细节等具体约束。原任务在各 run 的 `spawns/writer/prompt.md`，正文也完整保存到参与者记录。
3. 独立审稿读取本 run 的 `review_packet.json`，看到冻结输入和作者候选，按任务不读作者提案或主编意见。其实际输入包与最终修订候选不必相同。任务原文在 `spawns/reviewer/prompt.md`。
4. 主编对真实提议逐项采纳、否决、部分采纳或暂缓，保留简明理由、证据与落点。不能为展示而制造分歧。

后端/UI 实施人员在记录中标 `scope=implementation`，不冒充故事作者。当前页面把他们保留在完整创作日志里；故事输入目录集中列出实际故事参与者。

## UI 中的查看路径

`魔兽世界 → 2_故事 → EP1 → runs → run1 / run2`。每 run 有三个目录：

```text
输入与规则
  输入快照与完整清单
  故事设定
  背景与事实来源
  流程规则
  实际任务指令（含审稿输入包及已留存追加指令）
  运行与模型设置
产出
  候选故事、候选状态变化、候选虚构设定
  完整候选数据、作者初稿与因果骨架
过程
  创作日志、完整回复、审稿结论
  完整事件时间线、逐项提议与取舍、主编摘要
```

这些是管理应用中的逻辑 soft link，定位本 run 的冻结字段或已登记审计文件。每项显示来源、取用范围和指纹；独立文件须与历史登记 SHA256 一致才能展示内容，变化或丢失会显示缺口。规则内部引用若也被本 run 冻结，打开同 run 的快照；未留存的引用明确标注，不自动补读最新文件。
