# ep01 冷开场（s2）成片问题：根因与审查缺口

本文回答 follow-up 232 的前两问：① 这 5 个问题最初为什么会出现；② 审查机制为什么没抓到、缺了什么。第三问（测试体系）另见 `test_system_proposal.md`。

## 0. 结论先行

1. **问题主要出在设计层，不主要是 Seedance 演砸了。** 逐层追溯并经对抗复核后的结论是：st6、st7、st11 起源于故事稿，st2、st12 起源于分镜，生成层只是放大。也就是说，在花第一笔积分之前，这些问题就已经写在稿子里了。隔离条件下做了成片冷看复测：只给联系表加字幕，用独立子进程 `claude -p` 跑了 4 次。每次都报出 st6、st7、st11、st12，st2 一次都没报出，即 4/5。故事稿、分镜文字层面的干净复测还没做，列为测试体系的第 0 步。
   **更正**：本轮最早的三组「盲测」报的是 5/5，但工作流框架会把触发任务的用户原话转发给每个子代理，审稿人其实看到了这 5 个问题。之前写「隔离已核实」时只核了它读过哪些文件，漏查了这条注入，所以 5/5 作废。
2. **五个问题里有四个是同一个病。** st6、st7、st11、st12 都是这样：主角唯一一次主动的英雄动作，被一个跟人物无关的意外打断（自己摔、躺着、伤从天降、纸自己掉）。之后发生的每件事都不是他行动的结果。st2 是另一类：起因只写在文字里，没有任何一个镜头拍它。
3. **审查没拦住，不是因为检查少，而是因为没有「独立的眼睛」。** 新流程只有两种关口：一是人确认文字，二是机器查结构。读意思、看画面、按顺序看整场，这一层是刻意拿掉的。唯一的「看片」是作者自审：以单镜为单位，对照自己写的分镜，看 1 帧/秒的拼图。第一个按顺序看完 s2 的人就是用户，这时两轮出片已经花掉约 2,000 积分。
4. **同类问题遍布全集。** 对 82 镜的故事与分镜做了扫描并复核，确认 **39 处**同类风险，其中 20 处 major，分布在 s1–s10。s3–s10 还没出片，现在改不花积分。
5. **旧流程踩过同样的坑，教训随迁移丢了。** 同一部剧的旧流程有过同类反馈和对应规则：follow-up 034/035「杜克走着走着就摔了，这太假了」，038「观众怎么知道他们要做什么」，042「见狼低头」。2026-10-03 至 10-07 重启时，这些规则和工具被整体排除，也没有任何回归测试把教训固定下来。实测还表明，把旧的关键词闸门原样接回来也抓不住这次的 5 个问题。缺的是语义和画面层面的独立审读，再加整场连看。

## 2. 逐个问题

### 2.1 st2 · 亚伦为什么去捆绳

**观众看到的。** st1 的 0–4.5 秒，顶上两筐和麻绳完全不动：块匹配显示只有机位视差，没有相对下滑。绳一开始就是系好的。画面里唯一读得出的问题，是米莉压着一辆陷住的车。亚伦从修道院方向走来，边走边把信塞进衣襟；4.95 秒他的手握到绳上，位置恰好在米莉扶车把的手边，读起来像是来帮推车。st2 是另一种深褐方筐上的绕绳特写，开场就没有「松」的状态。

**根因（复核修正后）。** 起源在影视改编，生成层把它放大成「完全看不到」。

| 层 | 作用 | 要点 |
|---|---|---|
| 故事 | 潜在风险 | 一句话里同时放了两个问题：「陷在车辙里」和「车绳松了，最上面一筐正往下滑」。他先处理小的，故事里没交代理由。故事文本本身因果自洽，不是主因。 |
| 分镜 | **起源** | 起因没有归属任何拍点。st1 的拍点定为「车陷泥里」，st2 的理由是「技能要看得见」。起因只是 5 秒全景前 2 秒里的一个分句，与推车、打滑、入画挤在一起，画面里也没人对它反应。指南明写主镜头「看不清…小道具」、插入镜头「不应该…用插入掩盖动作原因」，没有用上。 |
| 参考 | 次要放大 | p475 锚点图和道具外观文字都是终态「系到另一侧」，与起始态矛盾。旧条没挂 p475 也没演出滑筐，说明这不是必要条件。 |
| 生成 | 放大 | 两条 st1 都没演出滑筐，这一拍掉了。 |
| 审核 | 漏拦 | 两条 st1 的审核都写了「滑筐不明显」，但没有严重度、也没有和 st2 的依赖关系，结论仍是保留。st2 保留的是补 p475 之前的旧条，筐和 st1、st3 对不上。没人看过 st1→st2 的切点。 |

**反事实。** 无法判定。像素估算用的是自设常数，被复核推翻。

### 2.2 st6 · 站位跳变 + 走两步就摔

这一条是两个独立缺陷叠在一起。

**(1) 站位。** st5 两人并排，st6 开场时亚伦却在米莉身后，随后绕到她右侧朝镜头走。故事和计划都没有这个问题：overhead 与 previz 静帧里，亚伦在画左、离镜头更近，然后横移挡到她前面。断点在编译和参考：
- v8 编译器把罗盘方向（面朝西、向西南跨一步）原样写进 prompt，没有「画左 / 画右 / 朝镜头」这类画面里的起始站位；
- prompt 里最强的空间信号是 bg1-8 场景图和它的「场景」行，两者都是朝北视角，与朝东的机位冲突；
- 机位视角的 previz 静帧已经画对了站位，但没有上传。

两条 take 都这样演，说明是系统性结果。

**(2) 「走两步就摔、像有行动障碍」：起源在故事层。**
- **故事。** 人物缺点「先伸手、再看脚下」被直接写成一个货栈工无外力地一脚踩空，和勇气挤在同一个动作里。决策记录只核对了同情来源清单，没人问这一摔在画面上会被怎么读。
- **分镜。** 跨一步就倒；机位放在狼的来路上，狼整镜不在画内，看不到威胁；坑从没被立成危险，overhead 里也没有坑这个物件，st6 因此被判为简单镜、不做 previz。
- **生成。** 把「冒失」演成了「残疾」：编译进来的场景行写「两道浅辙」，和分镜的「泥坑」矛盾；模型画成平路一滑、炸起特效般的泥浪、一条腿翘起的喜剧摔；「伸手拿锤」变成甩向推车的平衡动作；米莉也没后退。

另有两处连续性错误：st5 里亚伦手拎一把没包的大锤，来自 c1-1 三视图的持锤造型，而且 st5 没挂 p476，和 st6 背上的布包矛盾。另外，作者的 st5 审核写「两人没回头」，全分辨率帧里两人其实在 1.25–2.0 秒回头了，审核与画面不符。

**旧流程同类教训。** follow-up 034/035，用户原话：「为什么 duke 走到房前就摔倒了…这太假了」。当时定下的修法是「先问这一摔该不该有，先删改结果，不往前补原因」。这次不但重演，还出现了同一个反模式：故事的「一脚踩空」到分镜被改成「泥坑…泥没过鞋面，脚下一滑」，等于给摔倒补了一个能过闸的原因词，问题本身没变。

### 2.3 st7 · 摔倒后躺着不动、不看狼

**观众看到的。** 整整 4 秒，亚伦侧躺在画右，头基本正对镜头，只有眼珠斜到画左。扣除整体画面位移后，头部相对位移不超过约 11 px。狼冲到一个身位内、箭在一米外落地溅起泥冠、狼逃走，他都没有任何反应。狼也不是侧身逼近他，而是正面冲向镜头。整段约 29 秒的「狼」，主角自主的动作只有 st6 那一步、st10 伸手被拉，以及一句台词。

**按用户原话逐句归因。**

| 用户说的 | 起源 | 依据 |
|---|---|---|
| 「躺在地上」，被别人救 | 故事 | 从摔倒到被拉起，主角一直倒在地上，危险由伊根一箭解决 |
| 「摔倒的桥段本身太假」 | 故事（见 2.2） | 无外力自摔 |
| 「躺着不动、不知道在干什么」 | **分镜** | st7 被写成「狼扑、箭落」的事件镜：4 拍全给狼和箭，亚伦 0 拍、没有表情词，只有一个静态的「面朝西」。overhead / previz 只给他一个姿态，没有 react / gaze。编译器还注入了人物卡的常态神情「认真、有点拘谨」 |
| 「全程注视前方，不看狼」 | **生成 + 编译** | 模型把他的头转向镜头，违背 previz 里侧脸朝画左的人偶；又把狼改成正面冲镜头，人和狼之间没有视线关系。编译器只写罗盘方向，没写「亚伦在画右、3/4 侧脸朝画左」。st7 只有一条成功条，没有择优就收下了 |

作者审核写「撑起上身看狼」，与画面不符。

### 2.4 st11 · 手伤从哪来

**观众看到的。** st6 他向左侧摔倒，左手撑在草和泥的交界处，落点没有石子，他也没有疼的反应。st7 狼没碰到他。st10 米莉拉他的右手腕，他没有反应。st11 镜头拍到的是右手**手背**：一道干净、渗血、约 3 cm 的斜口子，像刀口或爪痕，手上几乎没泥。到 st12 这道口子又不见了。

**根因：设计层的因果缺口，故事和分镜共同造成。**
- **故事。** s4 的「Show me」需要一道掌伤，故事把它挂在一场与狼没有接触的软泥自摔上，原因只在揭示句里用一个定语交代：「手掌被石子划开一道口子」。用户说「就只是摔倒了」，意思是即便把石子拍清楚，软泥里摔一跤的分量也不够，所以要在故事层改。
- **分镜。** st11 原样搬进这个定语。st6 没有任何一拍让右掌碰地或碰石头：右手最后一次出现是伸向布包，倒下时是左侧着地。伤也没有写进 st12、st13、s3 的人物描述串。各镜字段是 follow-up 227 按场并行填写的，从没有人沿着「亚伦的右手」排一条跨镜状态轴；`state_changes.md` 也没登记这道伤。
- **生成。** 分镜写「掌心朝着自己」，机位却在他正前方，按文字画根本看不到掌心的伤。模型把伤画在了手背上。

**改的时候必须保留的**（s4 要用到）：
- 伤在右手掌心，小而浅，到修道院时还在微微渗血；
- 萨缪尔「Show me」要有具体对象，第一次请圣光就是治这道伤；
- 「一道小口子就耗得他扶桌喘气」立下「Enough for one. Maybe two」的力量尺度；
- 冷开场里他先问「Are you hurt?」，自己的伤擦一擦就不管了，这一拍要留。

### 2.5 st12 · 信无故掉出来

**观众看到的。** 第 0 帧纸已经离开衣襟悬在半空，0.25 秒出画，0–0.47 秒画面里没有头。他从水坑边捡起一个皱的小纸团，展开却是平整干净的信纸。

**根因（复核修正后）：起源在分镜，不在故事。** 故事原句是「他往裤子上擦了擦，**又去扶车**。怀里掉出一张折着的纸」，故事里本来就有能拍的触发动作：扶车时人会前倾、俯身。分镜把它拆成三镜：
- st11 写「转身朝推车走去」；
- st12 让他原地站定、背向推车，overhead 里面朝方向从 32° 改成 133°、速度为 0，纸在 0–1 秒自己滑出；
- st13 才是「弯腰用右肩顶住车尾」。

原因因此被挪到了结果之后，掉落又排在新镜第一秒、紧挨切点，模型没有前置动作可画。同一镜的机位要求本身也做不到：近景约 0.74 m（头到胸）、要求「纸和脸始终同框」，同时又要纸落到脚前。

故事层只在身份上有影响：报到信和父亲字条都放在「怀里」，外观一样；「是父亲的字」只在叙述里。观众因此分不清掉出来的是不是 st1 塞进去、s3 又递给维里的那封信。

**新流程的指南其实已有对口规则，但没被应用，也没人核对：**
- filming.md「确认行为能被镜头看见」；
- filming-shots「省略的信息观众是否已经知道」；
- filming-functions 插入镜头「交代细节归谁、为什么出现」；
- filming-series「跟踪道具的状态和时间线」。

**审核。** 作者用的 1 帧/秒拼图，第一格是 0.467 秒的帧，掉落从没进入审核视野；审核里写的「纸从前襟滑出」和「提交时已带湿泥」都不是从画面或日志核实来的。

## 3. 共同根因

| # | 根因 | 涉及 | 说明 |
|---|---|---|---|
| R1 | 用意外和巧合推剧情 | st6、st7、st11、st12；全集同类 8 处以上 | 自己摔、自己掉、自己滑开，敌人等主角准备好。人物缺点被写成肢体失误，没人检验它在画面上会被怎么读 |
| R2 | 文字到画面的翻译缺口 | st2、st11、st12、st6 | 原因、身份、意图只存在于叙述里（「车绳松了」「被石子划开」「是父亲的字」「伸手去拿锤」），画面上没有对应的东西；没有任何一步检查「观众在画面里看到什么」 |
| R3 | 在画人物没有拍点 | st7；全集同类 7 处 | 事件镜只写事件，不写在场的人做什么、看哪里；编译器给不出反应 |
| R4 | 跨镜状态没人管 | st11、st12、st6；全集同类 12 处以上 | 伤、泥、长包、纸、左右站位都在单镜里各写各的；`state_changes.md` 只记集级大事 |
| R5 | 编译丢了「画面方向」 | st6、st7 | 罗盘方向原样进 prompt；场景卡是朝北的描述，与机位冲突；道具参考是终态；previz 静帧没上传 |
| R6 | 只有作者自审，没有整场连看 | 全部 | 审核以单镜为单位、对照自己写的分镜，看 1 帧/秒、640 宽的拼图；没有严重度和依赖关系；没有独立审稿人；没有按播放顺序看整场（animatic 只在旧路径上，剪辑模块尚未设计） |
| R7 | 关口由作者代签 | follow-up 231 夜间授权 | 分镜修订的「确定」、出片、选条、审核都由同一个代理完成；确定关口只记一个哈希，不记谁确定的、依据什么 |

R1–R5 决定问题**会不会**出现，R6–R7 决定出现了**能不能被看见**。生成层的随机性（掉拍、朝向偏差、喜剧摔、左右镜像）不在我们控制内，按「不追求 100%」的原则交给择优和搁置处理（follow-up 234）。

## 4. 审查为什么没拦住，缺了什么

### 4.1 当时实际存在的关口（全部是绿的）

| 关口 | 查什么 | 本次结果 |
|---|---|---|
| story / filming / prompts 结构校验与确定指纹 | 字段、类型、ID、上游指纹 | 通过，三个模块都是 approved==current |
| overhead 闸门 `shot_overhead.py --all --check` | 键名、几何、碰撞；gaze / react 只在作者登记了才查 | 82 镜，blocker 0 |
| 编译参考门禁 | 参考有没有 | 通过 |
| 资料包 `shot_pack.py check` | 来源与指纹 | ok 82 |
| 每条 `review.md` | 作者对照本镜分镜自审 | 13/13 写「已审核」 |

真正读「意思」的只有三处：用户读故事散文，作者写决策记录，作者写审核。三处都不是独立的眼睛。

### 4.2 缺的四样东西

1. **独立视角的审看。** 隔离的成片冷看复测 4 次，每次都抓到 5 个问题里的 4 个，只漏了 st2。文字层的干净初测（中性提示词，每层 3 次，见 `test_system_proposal.md`「第 0 步初测结果」）只稳定抓到「无因自摔」：故事稿 1/3 个必要用例、分镜 1/4 个，按事先定的门槛都是 no-go——这些问题在文字里写得「看起来合理」，要画到画面上才暴露。所以最有效的一环是**出片后按播放顺序的整场冷看**（独立上下文、看联系表加字幕），文字冷读只作辅助。**这类审稿必须在工作流框架之外的隔离子进程里跑**，否则它会看到用户原话（本轮的教训）。
2. **按播放顺序看整场。** 5 个问题全是跨镜问题：因在前一镜（st2、st11、st12），站位要接上一镜（st6），反应要对着另一个画内角色（st7）。单镜审核结构上就看不见它们。
3. **把画面方向和状态写成可检查的数据。** 画左 / 画右的起始站位、每个在画人物每一拍做什么、看哪里，以及伤、泥、道具的跨镜状态轴。这几项一旦落成结构化字段，就能做确定性检查，不必靠人记。
4. **把教训固定下来的回归测试。** 现有 `test_episode_workflow.py` 的用例全是结构契约。旧流程 `beat_logic` 的 7 个单测一直全绿，却只用旧格式「0–8s」写成，对新格式「秒」完全失效（实测解析出 0 拍）。这正是 lessons L19 说过的「闸门写完要拿一条已知坏样本确认它真的报；测试要随格式迁移、跑当前真实数据」。

### 4.3 为什么不是「把旧检查接回来」

- 旧关键词闸门（`beat_logic` L2 / L3b）实测：格式适配后，st6、st11、st12 仍然不报。
  - 「摔进泥里」不在摔倒词表里；
  - 「泥…滑」被当成合格原因「湿滑地面」；
  - 「划出…口子」不在受伤词表里。
- 扩充词表后，换个措辞照样能过闸。
- 用户的真实问题是「该不该摔」「像不像行动障碍」，这类判断关键词抓不住。
- 用户已决定删除旧流程、从零开始（follow-up 233）。旧流程留下的是**问题类别和用户原话**这类知识，进入新测试体系的回归用例；代码一行都不沿用。

## 6. 修复方向（需要用户决定的创作修改）

故事和分镜的修改属于创作方向，按「下游不擅自改上游」走修改请求，由用户确定后再动。推荐方案：

**A. 冷开场改成一次真实交手（故事层，一次解决 st6、st7、st11）**
1. 亚伦跨到米莉前面，去扯背上布包的绳结。结是他自己捆死的，解不开。缺点「先伸手、再看脚下」落在「没先想锤拿不拿得出来」上，正好接萨缪尔后面的「Keep it wrapped」。
2. 领头的狼扑上来，他抬起右手或还裹着的长包去挡，狼爪刮过掌心，扑力把他撞进车辙泥里。这是有外力的倒地；一身泥照旧，「You're the one in the mud」照用。
3. 倒地后他用脚蹬、用包顶，视线始终盯着狼；箭落下，狼逃走；他第一眼找米莉，然后才是「Are you hurt?」。
4. 掌伤在右手掌心，小而浅，满足 s4 的全部用途。代价阶梯要压住：这是他自己都不在意的刮伤，留出米莉受伤时的升级空间。

**B. 字条（分镜层，不改故事事实）**：掉落放在 st13「弯腰用肩顶车」那一下，故事原文本来就是「又去扶车」时掉出；报到信和字条在外形上区分开（封好的公文 vs 撕下的小纸条），s3 递信时观众分得清。

**C. 捆绳（分镜层）**：给起因一个自己的拍点。例如米莉一用力，车一晃，顶筐歪出车栏、葡萄往下撒，亚伦第一下是扶住筐，然后才重新捆。起因看得见，手艺这一拍也保留。

**无论选哪种都要做的（执行层）**：
- 编译写出画面方向（画左 / 画右 / 朝镜头）；
- 每个在画人物每一拍都要有动作和视线；
- 排出跨镜状态轴（伤、泥、长包、纸）；
- 画内人物的随身道具挂到该镜；
- 整场按顺序连看后再保留。

这几条也是测试体系第一批回归用例的来源。
