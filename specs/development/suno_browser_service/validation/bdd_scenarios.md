# 行为场景

| 场景 | 输入与动作 | 可观察结果 |
|---|---|---|
| BDD-01 普通音乐任务 | prompt 含中文/换行，instrumental true/false，mp3/wav；网页表单确认后生成 | 正确填值；一次 Create；按网页确认的实际新增数量逐条收取，默认两首不作为固定成功断言 |
| BDD-02 多调用方 | 同键同参数重复请求；同键改 prompt、format 或 target；不同键并发 | 原任务/冲突/排队三种语义明确；重复请求与恢复不增加生成次数 |
| BDD-03 账号可恢复障碍 | 独立登录命令启动专用 profile；后台遇登录失效或验证码 | 不收密码；保留任务；人工完成登录后有明确恢复操作，绝不对不确定提交再次 Create |
| BDD-04 防误收 | 预置旧歌曲、延迟出现的新歌、同 prompt 手工生成、无关联第三首、歌曲列表重排 | 仅持久确认属于本提交的 URL；无法确认则暂停；仅“比基线多”不足以证明归属 |
| BDD-05 官方导出 | 歌曲生成中、下载菜单尚未可用、WAV 无权限、第二首下载失败 | 等待有界；不转向私有接口或公开播放流；保留已成功第一首；恢复仅补收 |
| BDD-06 明示环境能力 | 本机后台 profile 与 Browserless native 分别启动 | 每种模式独立报告连接、登录、生成、下载结果；不存在远程实例时标未实测 |

网页 fixture 覆盖 BDD-01、02、04、05 的受控分支；BDD-03/06 的真实登录与远程兼容性须由对应环境证据确认。上述是计划，尚未执行。

## v0.2 场景
- 给定参考文件与明确 options，代理先上传本机并 plan；正式任务按 UI 填写并读回，收费操作先留痕。
- 给定页面缺少指定滑杆、模糊时长单位或多个相同控件，任务在 Create 前停止，返回具体校准原因。
- 给定未知生成结果，MCP/CLI 继续查询原 job；空 resume 拒绝，不用新键重提。
- 给定验证码暂停，新增模式不会绕过；本机查询、预检、已有成品下载仍可使用。

## v0.3 场景
- 用户从 UI 选模式/参考并预检：不生成，参数正确；正式提交与 agent 使用同一队列。
- 回执在服务器接受后丢失：页面刷新后保留原参数与键，重试得到同一 job，不产生第二次 Create。
- 已完成音频在 UI 加载：先鉴权及 SHA 校验，再试听与下载；真实提交未知时只显示原任务的恢复入口。
- 新任务为环境音、音效或歌曲：共用流程默认 Suno；准确配音/克隆等未支持时记录缺口，不静默走其他模型。
