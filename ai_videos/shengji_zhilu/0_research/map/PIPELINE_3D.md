# 从地图到 3D 世界 —— 四步链条

> 用户 2026-09-21 定的路线：**地图 → floor plan → scene / props → 3D 模型（先从头几个城开始）**。
> 本文把每一步的**输入 / 产物 / 闸门 / 谁来做**写死，因为**每一步的产物形态决定下一步能不能自动化**。
> 现状标 ✅ 已完成 / 🔸 进行中 / ⬜ 未开始。

## 全链条一眼

```
① 参考地图（游戏原图）        refs/{大陆}/{分区}/{区}/WorldMap-*.jpg        🔸
        │  人眼量坐标、读地貌
        ▼
② floor plan（俯视布局图）    scenes/{bg}/planning/{bg}_floorplan.png      ✅ bg1
        │  定「有哪些东西、各在哪、多大」
        ▼
③ scene / props 卡            2_世界观人设/{scenes,props}/                 🔸 已有 9 scene + 5 UI prop
        │  每个可复用物件一张卡（锁定串 + 锚点图 prompt）
        ▼
④ 3D 模型                     scenes/{bg}/_blender/{bg}.blend             🔸 bg1
                              props/{obj}/whitemodel/{obj}.blend
```

**方向不能倒**（`ai_video.md` rule 4e ①）：**图先行、3D 在后**。
锚点图是纯文字自由生成、零参考图；**绝不拿白模 / 灰模渲图当出图参考**——那会把生成图的质量上限锁死在方盒子水平。
此坑在 object 与 scene 上各踩过一次。

## ② floor plan ✅（北郡已完成）

**这一步是本链条的枢纽**——它把「一张画」变成「一组有坐标、有尺寸的东西」，下游才有得吃。

**输入**：① 区域地图原图（量位置）② 世界树的 `coords`（已有 348 个真坐标）③ 场景卡的锁定描述符。

**产物**（每个 bg 一套，落 `scenes/{大陆}/{区}/{bg}/planning/`——2026-09-22 起 scenes 按世界层级嵌，`大陆/区` 是索引层，bg 编号见 `scenes/registry.toml`）：

| 文件 | 内容 | 谁消费 |
|---|---|---|
| `{bg}_floorplan.png` | 俯视布局图：地面轮廓 + 建筑组方块 + 道路 / 水系 + 朝向箭头 + 比例尺 | 人眼确认 |
| `blocks.toml` | **结构化的那一份**：每个方块 = 名字 + 中心坐标 + 尺寸 + 旋转 + **是否要建成 prop** | ③ 与 ④ |
| `{bg}_route.md` | 走动镜的航线表（离地物距离 / 航段 / 方向） | rule 4j |

**已有的一半**：`tools/shot_plan.py`（rule 4j，2026-09-20 用户定调「先给我一个 floor plan，让我知道从哪飞到哪」；2026-09-21 改名，航线图叫 flight plan）
已经能出**航线图**，但它的数据源是 `previz_config.toml` 的 `[[机位]]` + 世界坐标表——
**那是「镜头怎么走」，不是「这个地方有什么」**。本步要补的是后者。

**两条硬约束**：
- **坐标只有一个出处**（rule 4i ①）：`blocks.toml` 里的位置必须可回溯到世界树的 `coords` 或从地图上量出的百分比，
  **不许两份文件各写各的字面量**——尺度抄第二份不会报错，只会让图上的城与航线错位，而且看上去毫无破绽。
- **`blocks.toml` 是示意不是几何真相**：真几何在 `.blend`。方块只回答「有什么、在哪、多大」。

**✅ 前置已决**（2026-09-21 follow-up 004）：**只上北郡山谷 + 闪金镇**，暴风城复用 sk2 的整城 blend，
哨兵岭 / 西部荒野第一季不建。所以 ② 之后**只有这两个地点往 ④ 走**，其余地点的 floor plan 仍值得做
（它是排镜与选景的依据），但止步于 ②。

## ③ scene / props 🔸

**用户的原话**：「所有可能的物品都可以是一个 object 再 props 下面」。这与仓库既有规则一致——

- **rule 4b-A**：每个 prop 一个目录 `props/p{N}_{名}/`，卡里每个可粘贴块**首行必须是路由键**，
  否则出的图永远落不进这个文件夹。
- **rule 4d**：object 走「图先行」五步——锚点图（纯文字、零参考）→ 正 / 侧 / 背派生视图 →
  用户在生成平台出 mesh → **必过闸门** `tools/whitemodel_normalize.py` → 七视角 + 转盘。
- **rule 4g §B 四问**（决定用什么建，按顺序问）：
  有现成资产 → 买；直线 / 模块 / 精确尺寸 → **脚本建**；有机曲面 + 有界 + 只有图 → **image-to-3D**；
  **环境 → 永不用 image-to-3D**（生成式给不出直角、统一地平面与重复开间节奏）。

**现状**：9 个 scene 主体（45 个 plate）+ 5 张 UI 元素 prop 卡。**实体 prop 一张都还没有。**

**从 floor plan 自动长出 props 的做法**：`blocks.toml` 里标了 `make_prop = true` 的块，
用 `tools/gen_object_cards.py` 批量出卡骨架（同构 prompt 走生成器，不手写 N 份——rule 4i ①），
再逐张补锚点 prompt。

**第一批该建什么**（ep01–ep03 实际入画的）：
修道院大门 · 训练场兵器架 · 狗头人的蜡烛与矿镐 · 葡萄架 · 木桶与板条箱 · 石拱桥 ·
南墙隘口的门 · 旧锤与木盾 · 铜币袋。**sk2 已有 22 个道具卡可复用**（炉石 / 钱袋 / 木桶 / 石井 / 店招…），
见 `0_research/sk2_reuse.md`。

## ④ 3D 模型 🔸（北郡进行中）

**顺序**（rule 4e ⑥：`.blend` 是图的下游）：

```
锚点图 → blender_build.md（给 Claude 的建模指令，引用锚点图）→ Claude 建 .blend → 校验产物
```

**两层分工**（rule 4g §J）：

| 层 | 产物 | 出什么 |
|---|---|---|
| **场景层** | `scenes/{bg}/_blender/{bg}.blend` | **只出 `.blend` + 校验 PNG**（平面图 `plan.png` + 各锚点机位的灰模透视），**不渲 mp4** |
| **shot 层** | `shots/shotNN/previz/` | **只有 shot previz 出 mp4** |

**环境的铁律**（rule 4g）：
- **生成构件，不生成建筑**：有机繁复的小件（窗 / 斗拱 / 瓦当 / 桥栏）走生成；平直重复的（墙 / 屋顶 / 街面）走脚本。
- **一致性来自「只有一份几何」**，不来自模型的记忆——全项目一份 `{world}.blend`，所有镜 previz 从它渲。
- **几何精度按镜头接近度分级**：贴身而过＝真立面 / 中景＝体块+屋顶形制 / 远景＝纯体块 / 看不到＝不建。
  **镜头先于几何**——先画长镜头路径再定精度。
- **一镜内主体数 ≤ 8**（rule 4g ⑥，硬约束）。

**先从哪几个城开始**（用户：「可以先从一开始的几个城市开始生成」）：

**用户 2026-09-21 定的范围（follow-up 004）**：

| 序 | 地点 | 集数 | 第一季建不建 | 说明 |
|---|---|---|---|---|
| 1 | **北郡山谷 + 修道院** | ep01–ep03 | ✅ **建** | 封闭河谷、体量最小、四面封山不用建远景。`tools/build_northshire.py` |
| 2 | **闪金镇** | ep04–ep07 | ✅ **建** | 五六栋房 + 一个十字路口，模数清晰；沿用北郡同一套模数 |
| 3 | **暴风城** | ep08 | ♻️ **复用不新建** | 吃 sk2 的 `tools/build_stormwind.py`。走廊只覆盖 sk2 航线，**光明大教堂那一段真要拍时再扩建**，不提前建 |
| 4 | 哨兵岭 / 西部荒野 | ep11–ep16 | ⬜ **不建** | ep11 的狮鹫航拍到时单独决策 |

**⚠ 已知的两个坑**：
- **`.blend` 由脚本确定性生成，不手改**（rule 4h ④）——手改过的 blend 没有可审阅的来源；改几何 ＝ 改脚本重跑。
- **previz 批量任务不许重叠跑**（rule 4h ⑥）——`TaskStop` 杀 shell 不杀已 spawn 的 `blender.exe`，重叠会报假失败。

## 下一步的最小闭环

**不要一上来铺全部 50 个区。** 建议先把 **北郡山谷**一个地点走通全链条 ①→②→③→④，

理由：这条链有四步，每步都有自己的坑；**一个地点走通的信息量，远大于五十个地点各走一半**。
