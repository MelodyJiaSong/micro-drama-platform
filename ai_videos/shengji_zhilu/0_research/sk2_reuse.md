### 2.3 场景主体（13 个 · 全部 16:9）

**这一类是 16:9→9:16 唯一真正吃亏的地方**，原因有两条，且第二条比第一条严重得多：

1. **构图不可裁**。2048×1152 中心裁成 9:16 只剩 648×1152，**左右各丢 70%**。sk2 的场景板构图是横的（街的纵深、运河的走向、广场的开阔），裁完不是变窄，是**取景意图整个作废**。
2. **更要命的是：场景板在本仓的纪律下根本不进生成模型**（`divergence #8`：一张游戏截图都不上传；`#108` 同）。场景板的用途只有两个——**给人眼定形制**、**转写成中文锁定串**。**这两个用途都与画幅无关。** 所以「16:9 不能用在 9:16」这个担心，**在本仓的工作流里其实是个伪问题**；真正的问题是**取景方向**：竖幅要的是**仰角 + 纵向堆叠**（尖塔、高窗、光柱），而 sk2 的板子大多是横向平视。

## 5. 跨系列复用的机制问题

**问题的形状**：`CLAUDE.md` rule 4b-B 的 `.link.json` 指针是为**同系列跨集**设计的（`hy1` → `hy2`）；`_series/` 共享目录也是（`ai_videos/{series}/_series/`）。本剧 `ai_videos/shengji_zhilu/` 是**扁平剧、另一个系列**，两套机制**在设计意图上都不覆盖它**。

### 先把代码事实查清楚（三条，均已核源码）

| 事实 | 出处 | 含义 |
|---|---|---|
| **`asset_link.read()` 不检查系列归属** | `libs/common/asset_link.py` —— 只校验 target `parts[0] == "ai_videos"`、无 `.`/`..`、resolve 后仍在 root 下、不是 symlink、是真文件 | **跨系列 `.link.json` 今天就能解析，零代码改动** |
| **tree reader 把链接节点的 `path` 设成 target 的路径** | `tree__reader.py:_link_leaf()` —— `node = self._leaf_for(self._root / link.target_rel)`，再覆盖 `name` / `is_link` / `link_at` | `/api/media` 照常服务（路径仍在 `ai_videos/` 沙箱内）。**但节点的 `path` 会指向另一部剧的 drama root** |
| **扁平剧不会触发 `series_key_conflict`** | `series_shared.shared_dir()` —— 只有 `drama_dir.parent` 带 `series.json` 才返回共享目录，否则 `find_conflicts()` 直接返回空 | `shengji_zhilu` 在 `ai_videos/` 下直挂，**冲突检测机制对它整个不运行** |

### 三个方案

#### 方案 A — `.link.json` 跨系列直指（最小改动）

在 `shengji_zhilu` 的资产目录里放 `{filename}.link.json`，`target` 写 sk2 的路径。

```json
{ "target": "ai_videos/shikong_lvxing/sk2/2_世界观人设/characters/c31_暴风城卫兵/c31-1.png",
  "note": "跨系列复用 · 同锚点同画风，卫兵形制一字不改（sk2 c31）" }
```

- **`DownloadsImporter` 路由键**：不受影响（扁平剧，冲突检测不运行）。**但链接目录会占掉本剧自己的键**——若原样搬 `c31_`，本剧的 `c31` 就被占了。**解法：链接目录用本剧自己的键重编号**（如 `c13_暴风城卫兵`）。安全，因为**复用卡按 rule 4b-B 不带任何图 prompt**，永远不会有下载往里落，键只是命名空间占位。
- **`assets.json`**：新增 **0 条**（字节仍只在 sk2 路径下）；只多几个几百字节的 tracked json。
- **webapp 树渲染**：`drama_ref` 不受影响（本剧仍是 2 段扁平剧）。**但链接叶子的 `path` 跨到 `shikong_lvxing/sk2/…`** —— CLAUDE.md 明令「**no consumer may re-derive the drama root from path depth**」，遵守这条的消费者不会出错；**任何违反这条的消费者会在这里第一次暴露**。可以把它当成一次免费的合规测试。
- **代价**：**单向依赖**。sk2 删一张图、改一次目录名，本剧当场断链（`asset_link.read()` 返回 None，树上那个叶子直接消失，**不报错**）。

#### 方案 B — 提出 `ai_videos/_wow_vanilla/` 共享库

`drama_ref` 已经明确「`_`-prefixed 段在两级上都不是剧」，所以 `_wow_vanilla/` 是个**合法的系统库位置**（与 `_actors` / `_bgm` 同级同性质）。把两剧共用的东西（§2.4 的 A/B/C 三样 + `c31` 卫兵卡 + `p15/p16/p20/p22` 等通用物件）搬进去，**两边都用 `.link.json` 指过去**。

- **优点**：单一出处（rule 4i ①），两剧**对称**——谁都不是谁的下游；规则演进只改一处；第三部魔兽剧零成本接入。
- **代价 1**：要**动 sk2 的既有产物**（挪已出图的卡）→ 撞上 CLAUDE.md 2026-09-06「规则变更默认只对新增与改动的产物生效，**不回溯旧剧**」。**这是一次显式迁移任务，得用户发起。**
- **代价 2**：`_` 库不在 `drama_dirs()` 的返回里 → webapp 左树**根本不渲染 `_wow_vanilla/` 本身**（只有链接叶子会在两部剧里各显示一次）。要让它可浏览得改 `exposed_tree` / 树渲染。
- **代价 3**：`assets.json` 的 key 会从 `shikong_lvxing/sk2/…` 变成 `_wow_vanilla/…` —— 按 CLAUDE.md，**路径就是对象键**，所以这是一次 R2 侧的 `CopyObject`（不花上传带宽）+ 清单重写。可行，但必须**先 push 后改**，顺序不能反。

#### 方案 C — 把本剧收进 `shikong_lvxing` 系列 ❌

`ai_videos/shikong_lvxing/shengji/` + 用现成的 `_series/`。零代码改动，但**语义是错的**：本剧不是《时空旅行》的一集（不同画幅、不同 concept、不同 `episode_prefix`）。且 `find_conflicts()` 会把两边同键判成 `series_key_conflict` —— sk2 的 `c31` 与本剧将来的 `c31` **必然撞**，每次导入都要人工裁。**不推荐。**

### 推荐：**A 起步，B 作为演进目标**，但两者都有一条**先决条件**

> ## 🔴 先决条件：先把 sk2 的字节推上 R2
