## 一个技能一张卡

目录 **`characters/c{英雄号}_{名}/skills/k{英雄号}{槽}_{英文名}/k{英雄号}{槽}_{英文名}.md`**——技能放在施法英雄的目录下（用户 2026-10-18 follow-up 010）；本目录 `skills/` 只留本约定和 2026-10-18 搬家前的请求日志。键 `k{英雄号}{槽}`：英雄号＝人物卡 c 号，槽＝1–4（按研究分卷与人物卡「技能画面」的顺序，Q W E R 依次 1 2 3 4，不是快捷键）。例：斧王 c65 的狂战士的怒吼＝`k651`。召唤物、物品主动效果以后同样立卡（键另定）。

编号随人物卡，不另领号；卡改名只改名字，不改键。人物卡「技能画面」节保留为概要，**技能的唯一出处是技能卡**；两者冲突时以技能卡为准并回改人物卡概要。

## 尺度换算（锁定）

**用户定（2026-10-18，follow-up 006）：技能整体放大——游戏单位 × 2 cm 换算成米**（原按 1 单位 ≈ 1 cm，换算出来的技能在真人画面里偏小）。例：狂战士的怒吼 300 → 半径约 6 m；沟壑 1000 → 直线约 20 m。

- 放大的：技能的作用范围、半径、直线长度、宽度、施法距离、弹道 / 光束长度，以及特效本身的高度与体量（热浪、光柱、冰墙、火焰的高宽）。
- 不放大的：英雄、小兵、召唤物的身材，武器与随身道具的尺寸，持续时间与动作秒数，贴身接触类的距离（近战一击、劈砍落点仍贴着目标）。
- 全图 / 全屏类技能不按数字换算，写「整片战场」等。
- 击退、击飞、拉拽、冲锋、跳跃等**位移距离**也 ×2（它们是技能范围，不是贴身接触）。
- 弹道 / 光球 / 法球的**直径**也 ×2，包括离手前在掌心凝成的弹核；统一写法：拳头大 → 约人头大（约 25 cm），人头大 → 约半米。
- 贴地雾、积水、泥沼等**高度**以不遮住小兵与施法者为限（不过腰），不机械 ×2；面积照样 ×2。
- 施法者的变身形态（如闪电球）、贴身护盾、武器本身按身材算，不放大。
- 卡里写换算时标「按 1 单位 ≈ 2 cm 放大换算」。

## 生成时怎么用

- `## Shot prompt 技能`：一段可直接写进镜头 prompt 的文字，只写这个技能看得见、听得见的样子，**不写游戏专名**（技能名、英雄名不进生成 text）。镜头里用到这个技能，就原样引用这一段，再由分镜补目标与机位。
- **峰值图** `{目录}_peak.png`：这个技能最绚丽的一刻，施法者用自己的立绘作参考、目标用兵线小兵立绘作参考，在中性战场上（16:9）。作为之后所有镜头的外观参考。
- **技能视频**（样片）：卡里 `## 技能视频 prompt` 一节写「视频参考:」行（上传顺序：施法者立绘、目标 / 友军小兵立绘、DotA 地图场景、峰值图、声音）与 `{目录}_clip` text 块（Seedance 格式，同镜头 prompt：时长、参考、参考用法、人物、场景、动作分秒、镜头、光线、台词、负面词、要求、声音）。小兵要有可见的倒下结果；场景用 `background/dota_map/` 里该英雄所在一方的地图区域。
  - `python tools/skill_pack.py sync <剧> [k651 …]` 建 / 更新 `{技能目录}/资料包/`（格式同镜头资料包）；`submit <剧> k651 …` 先出 480p 草稿到 `{技能目录}/drafts/`，用户看过再 `--stage final` 出正式条到 `renders/`；`poll <剧> k651 <submit_id>` 补收。**出片由用户决定**。
  - 一个英雄的 4 条技能视频按 Q W E R 顺序拼成一条 demo 短片（剪辑模块）。
- 分镜镜头字段写 `skills: ["k651"]`；Prompt 编译接入技能卡（写入 Shot prompt 技能段、上传峰值图 / 样片）**待做**，接入前分镜照抄技能卡文字。
