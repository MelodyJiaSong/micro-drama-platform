## 一个技能一张卡

目录 **`characters/c{英雄号}_{名}/skills/k{英雄号}{槽}_{英文名}/k{英雄号}{槽}_{英文名}.md`**——技能放在施法英雄的目录下（用户 2026-10-18 follow-up 010）；本目录 `skills/` 只留本约定和 2026-10-18 搬家前的请求日志。键 `k{英雄号}{槽}`：英雄号＝人物卡 c 号，槽＝1–4（按研究分卷与人物卡「技能画面」的顺序，Q W E R 依次 1 2 3 4，不是快捷键）。快捷键以 `0_research/parts/d15_技能名与快捷键.md` 为准（DotA 1 每个技能单独一个字母，不是 QWER；主据 6.83d 地图，人物卡「技能画面」小标题前的字母与技能卡首行「快捷键 X」都按它写；2026-10-18 follow-up 034）。例：斧王 c65 的狂战士的怒吼＝`k651`。召唤物、物品主动效果以后同样立卡（键另定）。

编号随人物卡，不另领号；卡改名只改名字，不改键。人物卡「技能画面」节保留为概要，**技能的唯一出处是技能卡**；两者冲突时以技能卡为准并回改人物卡概要。

## 尺度换算（锁定）

**用户定（2026-10-18，follow-up 006）：技能整体放大——游戏单位 × 2 cm 换算成米**（原按 1 单位 ≈ 1 cm，换算出来的技能在真人画面里偏小）。例：狂战士的怒吼 300 → 半径约 6 m；沟壑 1000 → 直线约 20 m。

- 放大的：技能的作用范围、半径、直线长度、宽度、施法距离、弹道 / 光束长度，以及特效本身的高度与体量（热浪、光柱、冰墙、火焰的高宽）。
- 不放大的：英雄、小兵、召唤物的身材，武器与随身道具的尺寸，持续时间与动作秒数，贴身接触类的距离（近战一击、劈砍落点仍贴着目标）。
- 全图 / 全屏类技能不按数字换算，写「整片战场」等。
- 击退、击飞、拉拽、冲锋、跳跃等**位移距离**也 ×2（它们是技能范围，不是贴身接触）。
- 弹道 / 光球 / 法球的**直径**也 ×2，包括离手前在掌心凝成的弹核；统一写法：拳头大 → 约人头大（约 25 cm），人头大 → 约半米。
- 贴地雾、积水、泥沼等**高度**以不遮住小兵与施法者为限（不过腰），不机械 ×2；面积照样 ×2。
- 施法者的变身形态（如闪电球）、贴身护盾、武器本身按身材算，不放大。
- 卡里写换算时标「按 1 单位 ≈ 2 cm 放大换算」。

## 生成时怎么用

**出片前先审时间轴（必要流程，用户 2026-10-24）**：每条技能视频提交前先 `python tools/skill_pack.py timeline dota_yingxiong <键>`，把「时间 | 画面」表交用户 review，认可后 `approve` 再 `submit`；改了时间轴就重审。**用户 2026-10-24 起授权免审**（「不要再找我confirm了，你要做什么就直接执行」）：表照写、照 `approve` 留痕，但不再等用户回复即提交。细则见[共用技能流程](../../../../.agents/skills/ai-videos-pipeline/resources/assets.md#技能)。

**出片后等用户反馈再重出（本剧必要流程，用户 2026-10-30，follow-up 295）**：「在自主权下，生成了一个video跑完了有问题，不能再次提交，必须等我反馈」。每条出片后（不论闸门过没过）直接给用户该英雄的预览页链接（README「英雄预览页」，follow-up 302），并经 cc-connect 发预览（飞书要打 zip），等用户回复后 `python tools/skill_pack.py feedback dota_yingxiong <键> "用户原话"` 记进该条 `user_feedback.md`，才能再提交；`skill_pack submit` 与 `skill_run` 都强制（剧级登记表 `[policy] wait_user_feedback_after_render`）。自主授权不越过这一条。

**一镜到底与取景（follow-up 295）**：用户 2026-10-30「一镜到底这个要求是对所有的英雄技能video生效的」——本剧**所有**英雄技能视频都必须一镜到底：出片前 `spec.onetake` 机检规格里写明一镜到底 / 不剪切（2026-10-30 时有 15 张旧卡没写，下次出片前补），出片后 `qc.py gate` 对 skills/ 下的出片自动按一镜到底查剪切（剧级 `[policy] skill_video_onetake`）。峰值图必须与开场图同一取景（以开场图为底图只改动作和特效），出片前 `keyframe.framing_match` 机检边缘重合 ≥ 0.62；出片后 `motion_check` 的剪切检测自动记 `video.onetake_cuts`。取景不一致时模型会在特效那一刻切镜。

**一条龙跑（本剧，follow-up 282）**：规格与关键帧 prompt 写好后，用 `python tools/skill_run.py dota_yingxiong k421 k422 … --auto-approve [--allow 检查id=用户原话 --followup NNN]` 一次后台启动，自动依次做：缺的开场图 / 峰值图（`planning/<图名>.txt` + `.refs`）→ 资料包 → 出片前机检与多视角审稿 → 闸门 → 时间轴留痕（本剧 2026-10-24 授权免等）→ 720p 正式条 → 出片后 motion_check / 多视角审稿 / 闸门；几条并行、可续跑，只在要人判断时停下（`--status` 看每条停在哪）。出片前审稿里「画面无法验证类」（如体型换算）第一轮就交用户定，不拖到第 3 轮。出完的图和拼图代理仍要亲眼看。

**后续所有英雄技能 demo（follow-up 084）**：遵循[共用技能表演与命中/死亡参考流程](../../../../.agents/skills/ai-videos-pipeline/resources/assets.md#技能)。施法者先有明确视线、武器/手势目标与重心动作，随后可见命中和受击反应；范围攻击读清爆心/主目标与旁边波及。致死时实际上传受击者自有死亡视频、明确背景/音轨不复用，并核对每只敌人至遗骸的对应；m4 使用小兵仰倒、收爪、干缩留骨，不能套英雄死亡。增益、被动、控制技能按其机制表现，不强行全员死亡。卡稿与本次结果冲突的“不可倒地”等先清除，峰值图只锁形制，不能把角色锁成静止摆拍。

- `## Shot prompt 技能`：一段可直接写进镜头 prompt 的文字，只写这个技能看得见、听得见的样子，**不写游戏专名**（技能名、英雄名不进生成 text）。镜头里用到这个技能，就原样引用这一段，再由分镜补目标与机位。
