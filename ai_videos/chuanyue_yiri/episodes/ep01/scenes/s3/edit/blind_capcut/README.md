chuanyue_yiri follow-up 039；工具 ai_video_management follow-up 354（`tools/edit_blind_test.py`、`tools/mcp_request_log.py`）。

**要回答的问题**：同样的素材、同样的说明、全部能商用的前提下，CapCut 能不能剪出比现有流程更好的成片。

**这是试点**：场三三条素材共 55.2 秒，成片约 51 秒，剪辑空间小，主要比的是入出点、节奏和会不会伤到对白。试点先把上传、请求日志、合规机检、导出与盲审跑通；结论有苗头再扩到整集（26 条、约 6.5 分钟，有场间衔接与取舍空间）。

## 合规机检（`check`）

成片里每一样都必须来自素材池，否则判不合规：

- **草稿**：只许 `DRAFT` / `VIDEO` / `AUDIO` 片段；来源只许本测上传的 `vid://`；转场、特效、滤镜、字体、动画、模板、贴纸、背景图字段非空即违规。
- **画面**：每秒 4 帧，与素材池每一帧比；整体差 ≤ 0.03，10×10 像素分块的最大差 ≤ 0.035。
- **声音**：0.5 秒窗口与素材池音轨的归一化互相关 ≥ 0.95；连续 1 秒以上低于此值即违规（切点上的单个窗口只提示）。

校准（`check/`）：现有流程一方合规（块差最大 0.0068，声音 5% 分位 0.994）；CRF 28 重编码合规（块差 0.0177）；人为加 36px 字幕（16/16 帧抓到）、20px 半透明角标（全片抓到）、明显与很轻的背景噪声（各 8 段抓到）都判不合规。
局限：被测方若变速，声音音高会变，可能误报；那时看草稿与原因再定，不放宽阈值。

## 结论（2026-11-09，follow-up 046）

揭盲：**A = 现有流程，B = CapCut**（钥匙与 `pool.json` 承诺哈希相符）。

- **用户**：没看出什么区别。
- **模型盲审**（只看联系表、切点、转写，看不到动态与声音）：4 次里 3 次偏好 CapCut，理由都是场尾——CapCut 留着 Felix 摇头笑、回去摆面包；现有流程 v3 按整集独立审稿有意把这条尾巴收紧到 18.5 秒。唯一偏好现有流程的那次，理由是 CapCut 剪掉了 Felix 进门打招呼的开头。
- **两版实际差别**（按 `cut_v3.json` 与 `arms/capcut_stdraft.json`）：三个切点位置几乎一样（8.0 / 约 16.5–18.7 / 约 30.3–33 秒，都是素材自带的机位变化或拍点）。差别只有两处：
  - CapCut 把 clip_02 的头去掉 2.0 秒，Felix 1.84 秒说的「Salve!」被切掉一截。
  - CapCut 把 clip_03 留到末尾 22.0 秒，现有流程只留到 18.5 秒。
  - 另外 CapCut 没按要求出 24 fps，出的是 30 fps；还把两段音量调到 2 倍、3 倍。盲化时已统一响度，看不出来。
- **判断**：三条素材、55 秒的场，剪辑空间太小，CapCut 只做到和现有流程打平，没剪出更好的成片。代价是三条素材授予 CapCut 永久使用许可、积分花费不明、没有导出接口、不守帧率。**CapCut 维持「不用」**（`paid_services.md`、`edit-tools.md` 不改），也不扩到整集测试：README 开头定的扩测条件是「结论有苗头」，这次没有。用户 2026-11-09 确认：「先不用 CapCut」。
- 现有流程场三已到 `cut_v4`（2026-11-08，另一会话）。本测用的是 v3，结论不受影响。
