## A · 系列公式

### 1. 一句话

**一个好奇的外来旅行者被送到历史上真实的某一天、某座城，默认哪儿都能去：先从天上把整座城看一遍，再下地逛一整天、吃几顿、住一晚——城里的人不和她说话，她只对着镜头把看到的讲清楚。她什么都没改，只是在场。**

英文：*A curious outsider is posted to one real day in one ancient city, free to go anywhere. She flies over it, walks it, eats there, sleeps there — and talks only to you. She changes nothing. She was just there.*

简介定位句（四站固定第一句）：**「这不是历史课。旅行者是虚构的，事是查过的，画面是 AI 复原的。」**（Chloe 的「This is not a history lesson」定位句降低了观众对准确性的对抗心理，是实测有效的做法。判断：原句「人是虚构的」改为「旅行者是虚构的」——当地人不开口之后，片中唯一有台词的人就是旅行者。）

### 2. 十五条不变量（每一站都照这个走）

仿《荒野生活》圣经：任何一站违反其中一条，就不是本系列。2026-09-14 按系列 follow-up 008–010 与 §F.12 建议改写（原十三条中 I-6「结局三选一」、I-7「3 位受访者」作废，编号由新条目顶替；新增 I-14 / I-15）。

| # | 不变量 | 说明 / 依据 |
|---|---|---|
| I-1 | **一站 ＝ 一城 ＋ 一天 ＋ 当天的大事** | 从清晨入城到次日五更醒来（**住一晚**），不重返同一天。当天大事三档：制度日（开市 / 放榜 / 节令）、工程日（落成 / 启航）、灾变日（**只做前一日**，远景无血；过夜段在灾变开始前收住）；比例约 2:1:1。**片名一律「时空旅行 · {站名}」**，如「时空旅行 · 汴京清明一日」；「第 N 站」只在发布文案里当编号，不用「集 / 剧」（合规 R1） |
| I-2 | **签名开场（叠在航拍长镜最后 8–10 秒的画外）** | 「今天是{年号}{节令}。你在{城}，距今{N}年。一切都和那天一样——只是，多了一个我。」英 *"It's {date}, {year}. You're in {city}. Everything is as it was that day — except I'm here."*（CBS《You Are There》70 年格式的致敬）。**旧版「黑场 + 零知识点」放宽为「一个数字或一个物件」**：「距今 N 年」就是那个数字，长镜画面里正在发生的一件事（如纲船放桅穿桥）就是那个物件（§F.12 读数 F7-5、建议 3） |

### 8. 教育与可信度机制（把「学到历史」做成结构，不靠观众自觉）

1. **密度合同**（I-9）：「学到」的体感来自**高频、短句、可验证的小事实**，不是长解说——每个事实 1–2 句 + 一个现代类比。
2. **≥ 20 条 human-verified 事实清单前置**：台词只从清单里长（D §4）；画面可截图指认的东西只允许 ✅ / ⚠️。
3. **三色角标 + 音效**：让观众建立「黄标 ＝ 推测」的条件反射——这本身就是历史素养教育。
4. **旅行者说知识与对照、字卡说出处**：当地人不开口（I-7），知识不借古人之口说出；事实核对完全交给只对镜说话的人——HH 的 Rattus 从不和剧中人对话、只对观众说（§F.12 读数 D1-3）。2026-09-14 前的「当地人说知识」已作废。
5. **每站 ≥ 6 段逐字原文引文**（食谱 / 法条 / 涂鸦 / 简牍）：Tasting History 的可核对锚点。

### 2. 可信度层级（全系列统一）

| 层级 | 定义 | 片中可用作 | 例 |
|---|---|---|---|
| **T0** 一手史料 / 出土文献 / 传世图像 | 当代人写的、出土的、当时画的 | ✅ 直接引用（可上字幕「据《东京梦华录》卷二」） | 《东京梦华录》、里耶秦简、《清明上河图》、庞贝涂鸦、《物价敕令》 |
| **T1** 学术专著 / 考古报告 / 学术数据库 | 有注释、可回查一手 | ✅ 引用其结论 | 程民生、沈从文、孙机、Beard、Price、Gutas |
| **T2** 严肃普及（作者有学术训练、有参考文献） | 可当导读，需回查 T0/T1 | ⚠️ 回查后升 ✅ | 森林鹿、吴钩、伊永文、Mortimer、Angela |
| **T3** 百科 / 媒体 / 自媒体 | 只能当线索 | ⚠️ 只做索引 | 维基、澎湃「私家历史」、知乎 |
| **T4** 影视剧 / 网文 / **生成模型默认输出** | 误传的来源 | ❌ 只作反例 | 清宫剧、《长安十二时辰》布景、模型默认 |

**关键判断（F6 判断 3）**：Seedance / Kling 训练数据里的「古装」主要来自影视剧，所以**模型默认输出本身就是误传的浓缩**
（清宫剧式「大人」、唐宋人物穿明代立领、罗马人满街托加、维京角盔）。锁定描述串不仅要写「是什么」，**必须写一句「不是什么」**——黑名单同时就是 prompt 负向词库。

### 3. 三级史实标签（✅ / ⚠️ / ❌）

| 标签 | 定义 | 文档里 | 片中视觉 | 片中口播 | 进 prompt |
|---|---|---|---|---|---|
| ✅ 史料确证 | 有 T0 直接记载，或 T1 结论且可回查 T0 | `tag: ✅` + source + 页码/URL | 默认可信；可在画面角落小字「据《XX》」 | 可直陈 | 允许；`prompt_string` 必须与 source 同义 |
| ⚠️ 合理推测 | T0 无直接记载，由旁证/同期同类/T2 综合推出；或学界有争议 | `tag: ⚠️` + 推测依据 + 替代方案 | 角标「推测」三秒 | 记者**必须**口播「史书没写，我们按……推测」 | 允许，`Shot context` 写 `史实: ⚠️ {fact_id}` |
| ❌ 民间误传 | 广为流传但与 T0/T1 矛盾 | `tag: ❌` + 正解 fact_id | **只在「纠错单元」出现**，画面打 ❌ 卡 + 正解 | 我以为 · 踩坑（当地人摇头或手势示意、旅行者对镜认错） | **禁止**进正片视觉；只允许进 `unit: 纠错` 的 shot，且 negative 必含它 |

三种标签用**固定三色角标（绿/黄/红）+ 固定音效**——让观众建立「看到黄标＝这是推测」的条件反射，这本身就是历史素养教育。中文版角标「据史料 / 推测 / 误传」，英文版「Attested / Inferred / Myth」。
**「常见误传黑名单」本身就是节目内容**（F6 读数 3）：每条都能做成「我以为 · 踩坑」的固定小单元（旅行者按误传行事、当地人摇头或手势示意、她对镜认错），这是「观众爱看」与「学到知识」两个目标的交点。

### 4. 每集 dossier 模板（固定 15 节，缺项写「未查」，不许删节）

路径：`ai_videos/{series}/{ep}/0_research/dossier.md`（阶段 0，在 `1_立项` 之前）；
公共库：`_series/sources.md`（来源库）、`_series/blacklist.md`（误传黑名单）、`_series/glossary.md`（各朝称谓白名单）——三者与 `series_bible.md` 并列，是跨集一致性的根。

| # | 章节 | 必填内容 | 主要来源类型 |
|---|---|---|---|
| 1 | 时空坐标 | 年号 / 公元年 / 季节 / 具体日期；**为什么选这一天** | 正史纪/志 |
| 2 | 城市地图与街区 | 城门 / 主街 / 坊市 / **旅行者路线（起点→终点，每个停靠点对应一个 shot 组）** | 城坊考、复原图、CHGIS |
| 3 | 衣 | 按阶层 × 性别列 3–5 套典型装束，每套一个锁定串 + 一张实物参考图 URL | 沈从文 / 孙机 + 博物馆 |
| 4 | 食 | 当季可得食物、烹法、餐制（几餐 / 分食合食）、饮品 | 城市志 + 饮食史 |
| 5 | 住 | 住宅形制、家具（**坐具！**）、灯具、取暖 | 考古报告 + 图像 |
| 6 | 行 | 车马船轿、路况、通关文书、宵禁 | 制度书 |
| 7 | 物价与货币 | **两个锚（米价、日工钱）+ 10 件商品价格，全部换算成「几天工资」**；货币实物形态 | 程民生 / 敕令 / 简牍 |
| 8 | 职业与社会阶层 | 旅行者会看到的 6–8 种人（静默；含 1 官吏、1 商贩、1 女性、1 底层） | 城市志「诸行」 |
| 9 | 节令与习俗 | 该日的仪式 / 禁忌 / 娱乐 | 岁时记类 |
| 10 | 语言与称谓 | 称谓白名单 / 黑名单；3–5 句当时口语（标 ⚠️） | 森林鹿 + 笔记小说 |
| 11 | 当日大事时间线 | 该年该月发生了什么（**记者的「新闻由头」**） | 正史 |
| 12 | 可观察的人物（静默） | 真实人物（有姓名有出处，片中只远景、不说话）≥ 2；典型人物（虚构但阶层 / 职业有据，供「跟着一个人」与街景选用）≥ 3；每人一句「镜头能看到他在做什么、手里拿着什么」 | 正史 / 墓志 / 涂鸦 / 简牍 / 城市志「诸行」 |
| 13 | 常见误传（本集） | 从黑名单挑 3–5 条 + 本集新发现 | blacklist.md |
| 14 | 未定与推测项 | 所有 ⚠️ 的汇总，写明推测依据与替代方案 | — |
| 15 | 参考来源 | 按 T0/T1/T2 分组，含 URL / ISBN / 页码 | — |

每条事实一行，YAML 化以便机检：

```yaml
- fact_id: kaifeng.food.007
  claim: 州桥夜市卖「旋煎羊白肠、鲊脯、㸇冻鱼头」等
  tag: ✅            # ✅ 史料确证 | ⚠️ 合理推测 | ❌ 民间误传
  source: 《东京梦华录》卷二「州桥夜市」
  source_url: https://ctext.org/wiki.pl?if=gb&res=712358
  tier: T0
  verified_by: human   # human | ai_draft（ai_draft 不得进 prompt）
  used_in: [ep03/shot05, ep03/shot06]
  prompt_string: "夜市摊位上摆着切成段的煎羊肠、腌鱼干、冻鱼头，用粗陶碗盛放"
  negative: "辣椒、红油、玉米、番茄、土豆"
```

**物价换算纪律**：必须用「篮子锚定」（一石米、一日雇工工钱），**绝不做「一两银子 = X 元人民币」**——物价板块是最容易翻车、也最容易做成爽点的板块（F6 读数 2）。

### 5. 机检规则（接进 `ai_videos__格式契约`，审计左移进生成器）

- **K-F1** 每个 shot 的 `## Shot context` 必须含 `史实:` 行，列出本镜用到的 `fact_id`（≥ 1）。
- **K-F2** 每个 `fact_id` 必须在 `dossier.md` 中存在且 `verified_by: human`。
- **K-F3** `tag: ❌` 的 `fact_id` 只能出现在 `unit: 纠错` 的 shot；否则 blocker。
- **K-F4** `tag: ⚠️` 的 shot，`台词:` 里必须含「推测 / 不确定 / 史书没写」之一（口播义务）。
- **K-F5** `negative:` 字段并集必须 ⊇ 本集「常见误传」节的所有条目关键词（辣椒 / 托加 / 角盔…）。
- **K-F6** prompt 里每个形制名词（幞头 / 褙子 / tunica / stola…）必须能在 dossier 第 3/5 节找到 `prompt_string` 原文（byte-identical，复用 rule 4b 锁定串机制）。

`fact_id` / `tag` / `negative` 做成生成器字段（对齐 CLAUDE.md「审计左移进生成器」），不合格直接 raise。

### 6. 调研流程 SOP（每集约 6–10 小时；首集建库 2–3 天）

1. **定坐标（30 min）**：用正史本纪 / 年表找一个「有事发生」的日子（庙会、放榜、大火、新法颁布）——这是本站「当天大事」的由头。
2. **读城市志原文（2 h）**：汴京读《东京梦华录》对应卷；长安读《城坊考》对应坊；庞贝读 Beard 对应章 + 涂鸦库按地址检索。边读边填第 2/4/8/9 节，每条贴原文 + 链接。
3. **读断代专著补衣 / 住 / 物价（2 h）**：只读索引到的页。
4. **建参考图库（2–3 h，用户 2026-09-13 硬要求）**：**每个场景 / 建筑 / 食物 / 服饰 / object 在写锚点 prompt 之前，先从网上找 ≥ 8 张历史参考图**（博物馆藏品实物、传世画局部、考古现场照片、学术复原图；来源优先级 Met CC0 / Wikimedia Commons / 故宫名画记 / 台北故宫 Open Data / Europeana / Pompeii in Pictures / Digital Florentine Codex / 考古报告图版），用 `tools/ref_fetch.py` 下载到该资产目录的 `ref/` 子目录并自动写 `refs.md`（每张：URL / 馆藏号 / 年代 / 许可 / 它证明哪个 `fact_id` / 能不能入画）。**锚点 prompt 里的每个形制词都要指得出是哪张参考图**；不要用模型「想象的古代」。参考图只进 prompt 与 Seedance 的参考槽，非 CC0 的不入画（合规 R15）。
5. **过黑名单（30 min）**：凡本集可能出现的都写进第 13 节与 negative。
6. **写锁定串（1 h）**：模板 `{形制名词}（{材质}，{颜色，用色名不用 hex}，{关键结构 2–3 处}），{穿着/使用方式}；不是 {最常见误传形制}`。
   - 宋·汴京·男性市民：`宋代平民男子：粗麻交领短衫（本白偏灰）、腰间系布带、头裹青黑色软巾、脚穿麻鞋；不是明代立领、不是清代长辫、不戴唐式硬幞头` / negative `立领 马褂 长辫 辣椒 玉米 塑料 现代纽扣`
   - 罗马·112 年·男性市民：`罗马平民男子：本色羊毛及膝短衣 tunica，腰间系绳，肩披深色粗毛斗篷，皮凉鞋；不穿托加；建筑为红瓦、灰泥墙、彩绘（不是纯白大理石）` / negative `toga on everyone, white marble statues, horned helmets, medieval castle`
   - 三条纪律：① 定稿即 byte-identical 复用；② 每串回指 `fact_id`；③ 串里必须有一句「不是 X」。
7. **顾问抽查（异步）**：r/AskHistorians（先搜 FAQ，按版规带出处提问）、简帛网（秦汉简牍）、高校公开课教师、博物馆教育部门。**带着 dossier 的具体条目去问**（「fact_id X 我标 ⚠️，依据 A、B，能升 ✅ 吗」），不问开放题。

**AI 辅助的边界**：让 AI 建索引、交叉质询 dossier 条目、起草 `prompt_string` 候选、翻译外文页、起草「旅行者要看、要试、要讲什么」；**不让 AI** 做无源问答、决定 ✅/⚠️、直出剧本当史料、替当地人编台词（本系列当地人不开口，知识只由旅行者依 T0/T1 讲出）。规则只有一条：**每条进 prompt 的事实，必须有人眼看过的原文页。** 这是与「AI 历史号」拉开可信度差距的唯一办法。

**中英双版**：dossier 只写一份（中文）；`prompt_string` 与 `negative` 双语；称谓表分中英两列。
**摊薄**：同城多集（汴京可做 6 集：夜市 / 相国寺庙会 / 科举 / 元宵 / 金明池 / 虹桥）可把调研摊到 3–4 小时/集。

## E · 合规与风险（中文平台为主，YouTube 为辅）

> 全部依据来自调研 F5（法规原文 URL 与生效日期逐条核对）与 F4（平台政策时间线）。结论先行：**所有监管口径反对的不是「穿越」，是「不尊重历史」**。

### 1. 定性：「AI 历史情景科普节目」，不是微短剧

- 片名与简介避免「剧」「第 N 集」「连载」式短剧包装，改用**「时空旅行 · 汴京清明一日」**式的节目片名，「第 N 站」只作发布文案里的编号；每站结构固定（航拍—抵达—逛访—考证彩蛋—片尾出处）。这样在广电定义要件上不构成「故事情节连续完整的剧集」，平台侧也不会被扔进短剧赛道（R1）。
- **旅行者三铁律写进系列圣经**：① 只观察不干预；② 不带现代物品改变历史；③ 不对历史结果发表「如果当年……」的假设改写。这是把「穿越」从「戏说装置」变成「纪录装置」的关键。
- 旅行者人设不得涉「冒充新闻媒体」：账号名 / 台标 / 胸牌不含「新闻」「日报」「电视台」或真实媒体 logo；简介声明「非新闻机构」（R4）。中文版用「探访 / 打听 / 蹲点」，不用「新闻 / 报道」（F3 §B）。

### 1. 十二条读数（按对立项的决定性排序）

**读数 1 · 「记者 / 穿越者第一人称走进历史」这个格式已在 YouTube 被证明，而且是单人 AI 频道做出来的。**
Chloe VS History 2026-03 开号，第一条《I time travelled to Ancient Rome! (Vlog)》1,472,878 播放，前 7 条 35 万–276 万，现粉丝 403,000（实测）。创作者 Laramy 已公开身份与工具链（knews.media 2026-08-16 一手访谈，核实 K02）；「被 Sky News 揭露后反而获奖」为转述、未能一手核实——但**主动披露 AI 身份没有带来可见的流量惩罚**这一点成立。
→ 格式风险已被别人替我们试过；我们要解决的是「第二个做的人怎么不变成克隆号」。

**读数 2 · 克隆号几乎全灭；起量的号第一条就是最强题材，且有辨识度的「人」。**
**逐字抄 Chloe 标题的号无一破 2 万**（Relax History AI 同题 12,228、Mira Vale 1,858、Emma 1,225），而**同格式换角度、换标题**的号有 2–12 万（Esmetimetravels 117,976、Veils of The Tudors 40,756、NovainHistory 19,197）——核实 K03。18 个近 12 个月开号的同类频道里，7 个在前 10 条内就有 ≥ 4 万的视频（Chloe / Esmetimetravels / Veils of The Tudors / Arthur Revives the Past / Toms Zeitreisen / Daniel Does History / Worlds Before Us），共同点：① 第一条就是最强题材（古罗马、伦敦 1300 黑死病、安妮·博林最后时刻）；② 题材是英语观众的常识锚点；③ 有辨识度的人或视角（自拍臂 / 第一人称手部 / 播客麦克风）。
→ **不叫「X VS History」、不把 AI 当卖点、把「记者」当卖点**；第一集必须是最强牌。

**读数 3 · 时长：9–13 分钟横屏；2–3 分钟短片作主产品全部归零。**
A 类（穿越 vlog）时长中位 **9m44**（Chloe 9–15 分钟、Esme 固定 10 分钟、Veils 6–18 分钟）；B/C/D 类 15–22 分钟；本月冒出的几个新号（Mara / Katie / Time Wrap Diaries）**全部 < 40 播放**（但它们时长混杂、各只有 1–3 条样本，「短 ⇒ 低播放」的因果不能从它们得出——核实 K07）。样本里 Shorts 极少（1674 条搜索结果中 ≤ 60 s 的只有 7 条，无一过 50 播放）；**竖屏价值未被本数据集检验**。
→ 主产品比《荒野生活》（4.5 分钟）长一倍以上；竖屏切条只做引流（Chloe 的 Shorts 150K–1.1M，且长片前先用 3 条同题 Shorts 试水）。

**读数 4 · 子格式回报：A（出镜逛城）与 F（历史人物访谈）赞率最高，纯旁白「24 小时」是拥挤的中低位。**
实测子格式表：A 穿越 vlog 赞率中位 3.45%；F 历史人物 AI 访谈 3.94%（Veils 10 条全过万、周更）；C 一天生活旁白 1.02%、中位 7,400；B AI 复原城市 tour 1.60%、中位 3,600（421 条样本，最拥挤）；E 动画 POV「Your Life as」中位 13.3 万（中国题材在此类反而最能打：《Rented Wife in Song Dynasty》45.8 万、《Your Life as a Eunuch》100 万）。

**读数 5 · 「中国历史 + 英文」在 YouTube 没有成功先例；「长安 / 汴京 / 临安」在中文侧已被验证。**
中国候选在英文 YouTube 最高单条：汴京 85,477（Amimisu 真人）、长安 139,196（timewarp）/ 133,000（光影史刻）；兰亭 / 景德镇 / 泉州 / 元大都相关搜索最高只有 670 / 330 / 63 / 4,317。克隆号里做中国题材的全部归零（Naya《长安宵禁》1.5K、Zara《Chang'an 744》583）。

→ **英文线先打西方常识锚点（罗马 / 庞贝 / 泰坦尼克 / 都铎 / 黑死病）**，中国集放在观众建立信任之后或用嫁接标题（「814 人的画」）；**中文线首集就上汴京 / 长安**。长安是唯一「外来者视角」也被中文受众验证的题材（640 万）。

**读数 6 · 「灾难前一日 / 最后一天」显著跑赢「普通一天」。**
F8：庞贝需求最大（Astraway 940 万），供给也最密；伦敦 1348 三条百万级（Arthur 127 万、Tim 141 万、Modern History TV 137 万）；泰坦尼克 Chloe 频道最高 276 万、其它频道 450–750 万；标题公式 `{城市} {年份}: {一句灾难/巅峰钩子}`。
→ 每集要有「当天大事」；灾难集不拍「沉没夜」而拍「启航日」，避开 90% 的供给。

**读数 7 · 「吃 / 穿 / 住 / 睡 / 上厕所」的具体日常最容易破圈。**
`What Did {某群体} ACTUALLY Do All Day?` 是单条爆款王（Zenn《Ancient Humans at Night》794 万、Ink Explainer 340 万、Sleepy Time Historian 259 万）；Daniel《Tudor Banquet》32–46 万、Worlds Before Us《Junk Food 1180》18 万；Chloe Rome 9.4 分钟数出约 30 个可核对事实（≈ 3.7 个/说话分钟）与约 25 个笑点（≈ 2.7 个/分钟），**笑点全部依附在事实上**。
→ 每集必须落到一个「今天的人会震惊」的日常细节；目标密度：说话段 ≥ 3 个可核对事实/分钟 + ≥ 2 个笑点/分钟。

**读数 8 · 真正的 NPC 对话是分水岭。**
Chloe Rome 版 NPC 不能说话（拉丁语被打假为 gibberish，**唯一被明确差评的语言做法**）；Titanic 版加了 6 段短对话（爱尔兰情侣、Liam、头等舱乘客、船长、乘务员）就成为频道第一（276 万）。
→ 我们的 TTS + 锁定 voice_id 正好补这个短板：每站至少一段 2–4 句真实问答；**绝不让模型生成古语**。

**读数 9 · 反 AI 情绪是真实的，赞率是温度计。**
标题打「(NO AI)」的 History with Dave 181 万、「Human Voiced, No Ads」46 万；批评 AI slop 的 Skallagrim 赞率 8.0%、TJ3 History《How AI Slop is Making up False History》17.3 万 / 3.36%；复原漫游 1.3–2.6%、Moving History《Titanic Passengers Brought to Life》449 万播放但赞率 0.42%。Kapwing 2026-06：TikTok 新用户信息流 59% 为 AI slop，History 类 33.5%（转述）。
→ 我们贴不了「NO AI」，唯一可占的对位标签是 **「Human-researched, sources listed」**；上线后以赞率 ≥ 3% 为健康线，< 1.5% 说明被当 slop 刷过。

**读数 10 · 「记者穿越」trope 的成熟惯例：语言不解释、当地人两档反应、一天 + 不能重返。**
语言：《You Are There》凯撒直接答 CBS 记者、Horrible Histories 古人说带口音的现代英语——70 年无人抱怨；Doctor Who 用一句「TARDIS 翻译场」解决全剧，且「翻译失效」可做剧情。当地人：逛街时视而不见（自然纪录片惯例），采访时把记者当正常媒体（《You Are There》），每集只许一次「入侵者」笑点。时间装置：一集一个事件、结局已知（You Are There）；日出到日落逐小时（Alberto Angela）；不能回到已去过的时间（Timeless）。出镜比例：《You Are There》记者只出声约 90%、TED-Ed 0% 出镜也有百万播放。
→ **记者出镜 30–40%，画外 60–70%**：画外解说不涉口型，双语 TTS 可共用同一段画面，四站成本减半。

**读数 11 · 《典籍里的中国》能搬进 5 分钟短片的零件只有几件，但件件便宜。**
一句台词完成穿越（「我是两千年后的读书人」→ 古人「你是？」→ 行礼，实测 13 秒零特效）；古人反问未来（「两千年后你们还读吗？」）；记者 = 观众替身 + 切镜遥控器（「您看！」）；**反向穿越收尾（带古人到今天看一眼）压成 20–30 秒 tag——整期泪点**；金句三复读；史料字幕卡。不能搬的：90 分钟多舞台、专家访谈间、几十群演（AI 一镜 ≤ 8 主体）、20 秒以上静场。YouTube 端「穿越对话」当标题关键词只有 2 千播放 vs 完整版 39 万——**标题要落到具体城市 / 事件 / 画面**。

**读数 12 · 单人产能与更新频率：月更 2–4 集足够。**
月更 2–3 条的 Chloe / Majestic / Matt 中位 24–58 万；高频号（Paladin 178 条/6 月中位 2.5K）靠量撞爆款；Chloe 单片成本 £300–800、数周、10–15 次返工（转述）。Tasting History（4.46M 订阅）靠一条英文正片 + 18 种人工字幕做多语言，而非分语言重做。
→ 预算花在每集画面一致性与封面上；返工成本要进预算（E12 手 / 脸伪影）。

### 3. 标题公式与封面模板（全部来自实测高播放条目）

标题：① `I time travelled to {地点} in {年份}! (Vlog)`（Chloe 7 条 35 万–276 万）② `What {城市} Looked Like {时间}` / `A Tour of {城市} in the {世纪}`（117 万 / 74–120 万）③ `{城市} {年份}: {一句灾难/巅峰钩子}`（127 万）④ `Why You Wouldn't Survive {a day} in {场景}`（97 万 / 137 万）⑤ `What Did {群体} ACTUALLY Do All Day?`（794 万）⑥ `{人物} Meets {人物} — The Interview That Could Never Happen`（10.9 万）。**不写「AI」字样**（Chloe / Esme / Veils 都不写）。
封面：A 类三张公式完全一致——**主持人在画面左/中、伸出手臂做自拍构图、瞪眼惊讶、时代服装、身后 AI 场景人群、右侧 2–3 个超大字（年份 / 地点）**；F 类：两张脸对峙 + 大字 + 两支麦克风；纯城市集：城市全景 + 年份 + 国旗。两套模板交替，还能区分「逛城市集」与「事件现场集」。
描述：「我做了这些事」清单体 + 定位句 **「This is not a history lesson. This is just what it actually felt like to be here.」**

### 8. 中文「记者」身份的替代与定型（F3 §B）

记者（食贫道验证「提问—追问」动作）可行，但要定义成「街头 / 探访记者」而非「主播台记者」；当代读书人（典籍）可作自称调性；探店博主（张良仁「考古探店」6 个月 91 万粉转述）**作为记者的固定动作之一（每集必吃一样）**；导游是「讲」不是「问」，会丢掉采访这一最强差异点；文物修复师作片尾「今生」对照人物；画中人 / 文物自述作被采访者阵容；穿越者的「麻烦」（没钱、不懂规矩）要有，身份不要。
定型：**主身份「记者」，动作集合 = 探店（吃）+ 导游（逛）+ 记者（问）+ 穿越者（惹麻烦）**；每集 1 记者 + 2–3 名被采访的普通古人 + 片尾 1 个「今生」对照。

### 3. 生产现实（开工前要认的账）

- **镜数约 30–45（单镜约 20 s），是《荒野生活》14 镜的 2–3 倍**；单人月更 2 站是上限；Chloe 单片 £300–800、单场景 10–15 次重试（一手访谈，K02）。返工预算要写进排产。**一镜 20 s 里任何一拍崩了整条重跑**，所以 hero beat（试吃反应 / 跟拍那个人抬头的一眼 / 航拍拔高的那一下 / 看一眼那句话）排在各自镜的片尾。
- **四类高风险镜**：① 手拿食物入口（试吃）——用「食物特写 → 反应镜」硬切；② 群像（市集 / 典礼）——一镜 ≤ 8 主体，其余远景剪影；③ 画面文字（招牌 / 涂鸦 / 铭文）——**禁止让模型「写字」**，用核对过的真实铭文或无意义纹样（F §6 E5）；④ **当地人的嘴**——模型默认会让画面里的人说话、对口型：每镜负向固定挂 `古人开口说话, 清晰可辨的古人对白, 路人对口型`，环境声写成「听不清字句的人声嘈杂」，交流一律写成具体手势（指钱串、摇头、递碗）。
- **每城一份整城 blend**（rule 4g：几何在 3D、长相在主体）：全城体块层给航拍，镜头贴近的片区换建筑白模。汴京「外城 / 内城 / 宫城三重城 + 汴河 + 御街中轴 + 虹桥 / 东水门 / 州桥三块细部」、长安「一百零八坊体块 + 西市九街区 + 朱雀大街」、罗马「七丘地形 + 广场 + insula 街」；同城多站直接复用。
- **3D 层是新增的大头**：每站 1 份整城 blend + N 个建筑白模 + 每镜一条白模动画（航拍与一镜到底是 S 档手写路径）。判断：首站 3D 层约占总工时三分之一以上（未实测，sk1 出片后回填 changelog）；Cascadeur 未连接时人物动作先用定式姿态，不阻塞。
- **每站的 prompt 负向词 ⊇ 本站黑名单**（K-F5），且锁定串必带一句「不是 X」（模型默认输出就是 X）。
- **光源条件化 / 痕迹措辞 / 镜内状态** 三条自检照 `CLAUDE.md` 既有规则执行（`tools/prompt_light.py`、`tools/shot_logic.py`）。

### 8. 整座城怎么建：Claude + Blender + Hyper3D + Cascadeur 分工与步骤

> 给你的说明（follow-up 010）。**目标**：每站的航拍开场、一镜到底和其余需要城市几何的镜，都从**同一座 3D 城**里出白模动画视频，上传给 Seedance 当**运动 / 机位 / 几何**参考；**长相**（材质、颜色、光、脸）仍由锚点图 + prompt + 人物 entity 给。
> **为什么非建不可**：长镜头会看到参考图覆盖不到的角度，模型只能编，这一镜编一个样、下一镜编另一个样；**一致性来自「只有一份几何」，不来自模型的记忆**（rule 4g §D）。
> 规范出处：`ai_video.md` rule 4d（物件 5-prompt + 白模闸门）、4g（环境：几何在 3D、长相在主体）、4h（previz / builder / 生成式 3D 工程契约）；本系列偏离 `specs/ai_video/sk1/divergence.md` #9（单体建筑走 image-to-3D）、#10（白模动画上传作参考）。sk1 的具体任务书：`sk1/2_世界观人设/scenes/bianjing/_blender/{city_plan.md, blender_build.md}`。

#### 第 1 步 · 调研 → 全城平面排版图（`city_plan.md`）

1. **输入**：本站 `0_research/dossier.md`（第 2 节「城市地图与街区」+ 各地点事实）+ 参考图库里的复原图、考古平面、传世画局部（各资产 `refs.md`）。
2. **Claude 起草 `scenes/{city}/_blender/city_plan.md`**：
   - **坐标契约**：+X 东 · +Y 北 · +Z 上，单位米；水面 / 街面高程；分区（Place）与各自世界偏移。
   - **两个尺度**：**全城层**（外城 / 内城 / 宫城、城门、河道、主街中轴、坊或街区轮廓——航拍用，数值允许取整到十米）+ **Place 层**（镜头贴近的片区，米级）。
   - **布局表（每行一个方块号）**：方块 | 要素（城墙 / 城门 / 河 / 街 / 桥 / 地标建筑 / 普通街屋）| 建法（`p{N}` 白模 / 脚本 / shot 层道具 / 留位）| 中心坐标 · 朝向 | 尺寸（米）| 精度级 A / B / C | 依据 `fact_id` | ⚠️ 推测。
   - **方块号 ↔ 建筑资产索引**：方块 1 ＝ `p8` 虹桥、方块 2–3 ＝ `p9` 脚店、方块 4–11 ＝ `p10` 民居单元……**同一个 `p{N}` 可以占很多个方块**（那是实例，只建一次）。
   - **ASCII 平面草图 + 每条长镜头的路径**（★ 起点 → ◎ 落点，标关键时刻）——**镜头先于几何**（rule 4g §F）：先画航拍与一镜到底走哪条线，再定哪里要建细。
3. **视觉核对**：出一张**俯视全景底图**（`city_plan.md` 里有它的 prompt 卡，路由键 `bg0-{M}`，零参考、纯文字、平涂色块、画面里不许有字）→ 在图上按表写方块号、画镜头路径，另存 `city_plan.png`。建城之后 Claude 再用 `tools/render_scene_plan.py` 渲一张真正的正交平面图 `plan.png`，与 `city_plan.png` 对照。**图与表冲突时以表为准**——图只给人看，builder 只读表。
4. **你能怎么帮**：在纸上或截图上直接画——「这条街应该再往北」「城门朝向反了」「这里少一座桥」「宫城比例太小」——拍照丢给 Claude，附一句改哪。**Claude 改表，不改图**；改完重出底图或平面图给你看。
5. **做完的样子**：表里每个方块都有号、坐标、尺寸、依据；每条长镜头路径都画在图上；`city_plan.md` §0「自查对账」写清盘上真实现状（rule 4i ③）。

#### 第 2 步 · Claude 写确定性建城脚本 `tools/build_{city}.py`

1. **唯一输入是 `city_plan.md` 的表**；解析失败直接 raise、不猜（表是契约）。调用：`blender -b --factory-startup --python tools/build_{city}.py -- [<out.blend>] [--qc-only] [--place X]`。
2. **脚本生成的（平直、重复、要精确，rule 4g §C）**：城墙（梯形截面挤出 + 马面）、城门台与门洞、街面、河道水面与河床、护城河、驳岸土坡、桥面板与桥拱、杈子 / 廊柱阵列、树 proxy。
3. **建筑先全部是占位盒**：每栋按表里尺寸放一个**同尺寸方块**，名字带方块号、collection 加 `_PROXY` 后缀——previz 与走廊校验不必等白模；第 3 步白模到位后**重跑即按方块号替换**。

#### 第 4 步 · 人物与动作

1. **默认：previz 里的人是参数化人形 proxy**——`tools/previz_rig.py`（关节人形，全部姿态关键帧打在它上面）+ 可选 `tools/previz_human.py`（MPFB 真人网格跟随关节，四肢手指读得出）；人物上 **ID 色 + 自发光**，建筑保持灰模。3D 必须给对的是**身高比例、走位与时刻、遮挡与接触、服装剪影**；脸与布料交给 Seedance（rule 4g §I）。

1. **每镜一个目录** `5_6_分镜与prompt/shots/shot{NN}/previz/`：`previz_config.toml`（本镜 3D 层唯一真相）+ `shot{NN}_previz.blend`（从 `{city}.blend` **拷贝**出来的副本，脚本只动副本，绝不写回场景源）+ `shot{NN}_previz.mp4`（rule 4h §A）。
2. **分档**：

| 镜 | 档 | 怎么出 |
|---|---|---|
| **航拍开场**（1–2 镜，I-14） | **S** | `shot{NN}_previz.py`：读 TOML 的机位路径关键帧（低空掠河 → 拔高俯瞰 → 俯冲落点），import 共享库（`tools/previz_rig.py` / `tools/previz_config.py`）；两镜时**第 2 镜 t=0 的机位 ＝ 第 1 镜末帧的机位**（位置与朝向逐值相同），这样 Seedance 端的首帧承接才接得上 |

| 单人 / 空镜运镜 / 室内 | **B** | 同一引擎 |

3. **两条禁止**（rule 4h §C）：不许把引擎拷进 shot 目录改（缺功能就改引擎，全仓受益）；per-shot 脚本**必须叫 `shot{NN}_previz.py`，绝不能叫 `build_previz.py`**（webapp 按文件名找脚本，同名会让合法产物看起来像 fork）。
4. **时间轴对齐**：TOML 关键帧 `t` 与 shot md `动作:` 时间轴逐拍对齐（rule 4h §B 1），机位转向时刻对 `分镜:` 行的各段起止秒；改一处必同步另一处；prompt 里出现的 config 数字写实际值，不留占位符。
5. **骨架**：TOML 骨架可以批量生成——`tools/gen_previz_scaffolds.py` 是按分镜总表出骨架的先例，但它写死了别的剧的常量（车、马、2.35:1）；判断：本系列由 `tools/gen_shots_sk{N}.py` 在生成分镜时顺手写出每镜 TOML 骨架更合「一份东西只有一个出处」（rule 4i ①），骨架出来后按镜手调坐标与时刻。
6. **渲 mp4**：引擎直接出；Blender 构建缺 FFMPEG 时退回 PNG 序列，再用 `tools/whitemodel_to_mp4.py` 合成。场景 blend 是零灯光的，previz 若渲成全黑，**在 previz 侧**补一盏弱定向光 + 极暗环境光，不给 builder 加材质（rule 4h §D1）。
7. **上传 Seedance**：shot md 的 `参考:` 行照 rule 12.4-C 写裸 `=>@`（`@` 后留空，你上传时手填）——`` `本镜运动参考(previz视频)=>@` ``、`` `bg{N}_{场景}/bg{N}-1.png(世界锚点)=>@` ``、`` `{旅行者}=>@` ``；航拍第 2 镜另加首项 `` `本镜首帧(上一镜末帧)=>@` ``。**previz 只给运动 / 机位 / 几何，长相只来自锚点图 + prompt**（divergence #10）；若实测 Seedance 把灰模质感带进画面，退回「previz 只做机位对账、不上传」，记 `specs/ai_video/sk{N}/changelog.md`。
8. **并发**：**Blender 批量任务不许重叠跑**——`TaskStop` 杀的是 shell，已经起来的 `blender.exe` 还在写文件，重叠会报出假失败；等 `{city}.blend` 定稿再批量跑 previz（rule 4h §F）。任何 Blender / Cascadeur 改动的最后一步都是**关掉 GUI、重开最新文件**（rule 4h §H）。
9. **做完的样子**：每镜一条 mp4，逐秒对得上 `动作:`；航拍两镜在同一帧交接、无跳；出片后逐秒对账，漂了**改 TOML 重渲，不手改 blend**。
