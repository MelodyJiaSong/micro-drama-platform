## 用法

把下面整段贴给 Claude，并把上面五张图挂进对话。

```text
任务: 照参考图校正 entropy_city 的 Blender 场景几何
参考: `bg1_广场/广场正向.png(世界锚点)=>@, bg2_主街/主街正向.png=>@,
       bg3_高架/高架正向.png=>@, bg4_隧道/隧道正向.png=>@,
       bg5_全城/全城斜瞰.png(整城布局)=>@`
       （路径相对 ai_videos/duikang_shangzeng/2_世界观人设/scenes/entropy_city/）
参考用法: 这五张图是这座城的唯一标准——布局、体量比例、层数、开间、相对位置一律以它们为准，
          现有 .blend 里与图不符的一律改。全城斜瞰定街区网格与天际线层次，
          四张眼平图定各地点的近景体量。**只做几何**：不建材质、不建灯光、不做装饰细节。

必须落实:
1. 真实米制。以车长 4.84m 为尺度校准基准——任何物件的尺寸都要能和它比对得上。
2. 空间契约（铁律，不得违反）:
   广场在原点；主街沿 +Y；高架沿 X 横跨在主街尽头；隧道沿 −Y。
   冲出广场朝 +Y、驶回广场朝 −Y —— 同一条轴、方向相反。
3. 广场→主街的走廊净宽 ≥14m 且全程无遮挡（此前有一栋 22m 宽的楼横堵在开口上，
   导致"车冲出广场"那一镜的车开不出去）。隧道口同理。
4. 按锚点图校正: 各楼的层数与高度比例、开间与进深、幕墙分格的疏密、
   商铺立面的高低交错节奏、护栏与桥墩的比例、隧道断面比例。
   图上读不出精确尺寸时，用图里的相对关系（几层楼高、几个开间宽）反推。
5. collection 分区: BG1_PLAZA / BG2_STREET / BG3_BRIDGE / BG4_TUNNEL / FABRIC。
   物件命名 {BG}_{ROLE}_{NN}，保持现有命名规律。
6. 只建镜头相关的体量。窗框、招牌、空调外机这类装饰**不建**——它们由出图模型画，
   建了既拖慢 previz 又诱使人按"好不好看"评判 previz。

验收（逐条做，并把结果报给我）:
- 渲一张正俯视平面图（tools/render_scene_plan.py），肉眼过一遍布局与走廊通畅
- 按每张锚点图的机位渲一张灰模透视（tools/render_scene_view.py），
  与对应锚点图**并排比**：体量比例、层数、相对位置、地平线高度是否对得上
- 报告整场包围盒尺寸与各 collection 的物件数

完成后:
- 存到 ai_videos/duikang_shangzeng/2_世界观人设/scenes/entropy_city/_blender/entropy_city.blend
- 平面图与灰模比对图存同一目录（它们是**校验产物**，不是出图参考）
- 重跑受影响镜次的 tools/previz/build_previz.py
```

## 这一步产出什么

| 产物 | 用途 |
|---|---|
| `_blender/entropy_city.blend` | **唯一交付物**。逐镜 previz 的几何源 |
| `_blender/plan.png` | 校验产物：正俯视平面图，人看布局用 |
| `_blender/check_{地点}.png` | 校验产物：与锚点图并排比对的灰模透视 |

⚠ **校验产物不是出图参考。** 它们只回答「几何对不对」，不进任何 prompt 的 `参考:` 行——
拿 blockout 渲图当出图参考，会把生成图的质量上限锁死在方盒子水平（rule 4e，此坑已踩过两次）。

## 之后

previz 视频（`shotNN_previz.mp4`）才是 blend 的最终用途：它进每个 shot 的**视频参考位**，
锁死机位、走位与时刻——**方向由它给，不由参考图给**。
