## 一、标准工序（四步 · 全片每一镜都走这条）

```
① 写 previz_config.toml      定：主干动作、人物与物品的位置、机位、轨迹、时刻表
        ↓  blender -b --python tools/previz/build_previz.py
② 出 shotNN.blend + 白模帧序列
        ↓  tools/whitemodel_to_mp4.py
③ 出 shotNN.mp4（灰模动态）
        ↓  上传到 Seedance 的 reference_video 位
④ Seedance 渲染               负：长相、材质、车漆、光色、特效、质感、次级运动
```

**这条流水线的全部意义在于把一件事拆成两个人干：**

| | 谁负责 | 具体是什么 |
|---|---|---|
| **骨架** | **Blender previz MP4** | 主干动作、谁在哪、朝哪、走到哪、什么时候动、镜头怎么走、多大、谁挡谁 |
| **血肉** | **Seedance** | 车漆反射、灰烬微粒、逆光金尘、冰面镜反射、粒子重构、毛发、皮肤、光的质感 |

灰模视频难看是**故意的** —— 它越像成片，Seedance 越会去抄它的画面质量。
`build_previz.py` 里的「素模化」就是为此存在：场景主档的材质一律换成中性灰，
"从源头保证它连'像成片'的机会都没有"。

## 二、由此产生的一条硬规则：prompt 不复述 previz 管的东西

既然走位与坐标由参考视频承载，**shot prompt 就不该再用文字重描一遍**——
两处一旦打架，模型会两边都不听。分工按「几何 vs 语义」切：

| 字段 | 归属 | 写法 |
|---|---|---|
| `走位:` | **previz 主管** | 只写**空间关系的铁律**（如「马恒在画面左、不超越车」），**不写坐标与米数** |
| `镜头:` | **previz 主管** | 只写景别与运动**性质**（如「侧向轨道横移」），**不写机位高度/距离/占画比数值** |
| `动作:` | **两者共管** | **保留分拍与秒数**（语义，Seedance 要读）；**去掉相对大小与画面位置**（几何，previz 已定） |
| `情节:` `场景:` `光线:` `渲染样式:` `负面词` | **prompt 独管** | previz 完全不碰 |

> 已出的 shot14 / shot20 / shot60 是在「18 镜选做 previz」的旧前提下写的，
> `走位:` 与 `动作:` 里仍带少量坐标性描述（如「距车约六米」「占画面高度约二分之一」）。
> **需按本规则回修**——见 §七 待办 4。

## 三、三档 previz（每镜都有文件，内容按需求分档）

`gen_previz_scaffolds.py` 自动判档，分布：**A 33 镜 ／ B 14 镜 ／ C 13 镜 ／ D 1 镜**。

| 档 | 镜数 | 建什么 | 解决什么 |
|---|---|---|---|
| **A** 完整建场 | 33 | 车 + 马 + 环境体块 + 机位动画 + 全套关键帧 | 轨迹、遮挡、尺度、并驾不越轴、时刻表 |
| **B** 简化建场 | 14 | 主体 proxy + 机位，无机位动画 | 构图占比、站位朝向 |
| **C** 时刻表 | 13 | 单主体 proxy + 动作关键帧，不建环境 | **「这个动作分几拍、每拍几秒」** —— 微距与车内镜的 previz 价值全在这里 |
| **D** 图形层 | 1 | 落版版式与文字动画时刻表（shot61） | 落版节奏 |

> C 档看起来"没什么可建"，但它恰恰是 follow-up 001 说的**动作细节**：
> shot04 的酒杯要「杯壁先透明→酒液失去容器→保持杯形一瞬→散去」四拍，
> shot60 的粒子要「漂浮→收拢→显形→落定」四拍——
> **每一拍几秒，是 previz 的关键帧定的，不是 prompt 猜的。**

## 四、关键帧 t ＝ prompt 动作时间轴（硬约束）

previz 的 `[["道具"."关键帧"]].t` / `[["角色"."关键帧"]].t`，
**就是** `shotNN.md` 里 `动作:` 字段那些 `0-2s` / `2-4s` 分拍的来源。

两处不一致 = blocker。previz 是**动作时刻表的唯一真相**，prompt 抄它。

## 五、F80 白模 —— 唯一保留真实几何的资产

**divergence（须记录）**：引擎既定分工是「3D 只做几何、不碰长相」。
但**本片的"长相"就是产品本身**，而 F80 的车体外形恰恰是 Seedance 唯一必然画错的东西
（2024 年底才发布，模型先验极弱）。故：

- **F80 白模保留真实车体外形**，走本次新增的 `形 = "模型"` 挂真实网格。
- 马、驾驶者、建筑、参照物**照旧用色块 proxy**，不做长相。

## 七之二、已实测通过（Blender 5.1）

61 份配置全部过 `tomllib` 自检；抽样三档在 Blender 里实跑 `--no-render` 均 **自检通过 ✓**：

| 镜 | 档 | 结果 |
|---|---|---|
| shot04 | C | 85mm 微距缓推，占画高 85% → 100% ✓ |
| shot25 | A | 跟随镜，车稳定占画高 35% → 35% ✓；马落在画左 x=0.14 ✓ |
| shot58 | A | 角色 proxy 建出，车 35% 恒定 ✓ |

### 实测中暴露、已修的三个坑

1. **TOML 中文键必须加引号**——`[全局]` 非法，须写 `["全局"]`；嵌套表写 `[["道具"."关键帧"]]`。
   （生成器现已内建 `tomllib` 自检，非法配置在写盘前就报错。）
2. **平移运镜的默认幅度必须按景别给**——85mm 微距镜用 8m 推进会直接穿过主体
   （实测占画高从 85% 掉到 41%）。现按景别给初值：大全景 12m / 全景 8m / 中景 3m / 特写 0.4m。
3. **跟随镜的车不能在 previz 里向前跑**——机位不跟着走，车会缩到占画高 4%（实测）。
   跟随镜里**车＝画框锚点，保持原点不动**；要 previz 定的是「其它主体相对车怎么动」，
   向前的绝对位移交给 Seedance（路面流动、环境掠过）。

### 实测中暴露、待手调的两个

4. **对冲镜的车向默认是反的**——shot17 实测占画高 35% → 3.5%（起近落远），
   而对冲应当是起远落近。骨架给的是通用 ±25m，需按镜改符号。
5. **越轴风险已被 previz 抓出**——shot32 实测马被解算到画面**右侧**（x=0.63），
   违反 `world.md` §五「马恒在画面左」铁律。需调 `方位角` 或马的 X 坐标。
   **这正是 previz 的价值**：这个错误在文字 prompt 阶段是看不出来的。
