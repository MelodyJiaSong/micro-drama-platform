## 三体系扩展 · 2026-10-25

先看 `systems.md` 的「三体系 Foundation」，再在图册搜索资产名、剑修、水、火或体系键 xian / yao / mo；管理UI沿用 `library.json.navigation`，新增“仙家体系扩展”“妖族体系扩展”“魔族体系扩展”三个大类。新增卡片在 `foundation/{体系}/{id}/card.md`，均由主数据生成。

- **仙家**：补齐心法、剑刀枪弓拳掌、五行与风雷冰阴阳星空术法、秘术、秘籍、灵性生命、灵兽、神兽、8个门派、世家、公共组织和门内派系；已有灵根、灵体、丹符器阵复用。
- **妖族**：以本相、妖脉、血脉、蜕变、化形与栖地为基础，独立建立养化药剂、蜕纹符、共生器、巢阵、族庭、学宫、迁徙与贸易体系。
- **魔族**：采用渊域原生生命、渊核与魔息循环的原创方案，独立建立稳核剂、核纹符、壳器、稳压阵、学派、家系、渊庭与跨界贸易体系。

妖族不是魔族；仙家是文明与传承，族源、修行道路、灵智和组织籍属分别记录。功法按类型／路线／元素／用途／施用通道交叉分类：例如回潮剑法同时属于武技、剑修、水系、防御与控制。门派、世家、公共组织、派系也分开；每个派系都有宿主组织。

26维度覆盖三套体系的大类与子类设计，187项是首批具体条目，不代表每个子类已批量铺满。新增条目按物件、生灵种型、依附灵体、功法过程、组织徽记、场所、结构状态、阵法空间和传播效果九种用途出图。静态功法过程图不代表动作视频，徽记不代表组织建筑，演示形体不登记为角色。当前出图与验收进度见 `STATUS.md`；本轮独立深审见 `qc/deep_review.json`，历史文字审查只对应各自原快照。

## 数据与状态

唯一资产主数据为 `library.json`，系统主数据为 [systems.json](systems.json)。研究出处及访问状态为 [sources.json](research/sources.json)。每条资产有功能、触发、使用条件、成本、克制、外观、状态设计、类型化关联、版本和图像信息。关联区分加工与运行，标明部分建模；不把所有条目冒称完整制造清单。

图像按 `props/`、`background/`、`traits/`、`effects/` 和 `foundation/{xian|yao|mo}/` 保存。各目录内 `card.md` 是主数据生成的卡片，`prompt_vN.txt` 是对应版本实际请求文本，`anchor_vN.png` 是候选图；以主数据所指版本为当前图。原图不覆盖。`image_jobs.json` 记录计划，`qc/images.json` 只收录与当前 PNG 哈希一致的审阅证据。

`planned / in_progress` 是未出图；`generated_unreviewed` 是已有图待审；`reviewed / reviewed_with_notes` 是通过概念审图；`revision_required` 需要修订；`failed_or_unknown` 保留失败或未知结果。文字定义已完成不等于图片全部通过。

所有生成走仓库 Codex imagegen 入口。请求审计见 `props/request_log.md`、`background/request_log.md`；traits/effects 的日志按现有解析器归入上级 `ai_videos/_shared/request_log.md`，每次请求目标路径可辨识归属。实际图像模型、质量参数和费用在服务未返回时保持未知。

## 维护与接续

运行 `python ai_videos/_shared/xianxia/maintenance.py --refresh`，更新图片状态、哈希、验收聚合、卡片、规则速览和图册；无参数运行只验证 ID、关系、模板字段、prompt 与已审图哈希。工具不调用生成服务。修改主数据后刷新，避免手改派生文件。

制作记录与独立审稿在 `.audit/adhoc_agents/2026-10-22/xianxia-assets-20261022/`。继续生成前先核对请求结果，已尝试但结果未知的任务不得自动重提。要修改图像，另写版本 prompt，经统一入口产生新文件，再独立审图。

旧目录 `ai_videos/_research/xianxia/` 维持留档状态。此库是可选资产源，不自动成为任何剧的既定事实；剧内引用需固定版本与资产 ID。

基础图片是概念锚点或机制示意；32项建筑设施、16项山川场景和4项新增体系场所需要正面、侧面、背面三面板设定图，实际出图与验收进度以 `manifest.json: three_view_sheets` 为准。三视图用于检查空间外观，不是可施工图、三维模型或视频；接入剧时仍需补具体空间布局与镜头方向，再同步镜头资料包。


制作管理UI入口：左侧点“仙侠”系列进入资产总览，展开可见“公用资产”，其下按中文大类 → 小类 → 资产名称展开；点击类别筛选图库，点击名称直接预览图片与三视图。`ai_videos/xianxia/series.json` 引用本库，后续具体剧在系列下建立各自子目录；这里的原图与规则保持唯一源。

分类唯一源为 `library.json.navigation`，当前 15 大类、115 小类，443 项各归属一处，不移动原物理文件。26个设定维度是另一层交叉检索，唯一源在 `systems.json.foundation`，其中的资产引用不另计资产。`presentation_jobs.json` 记录原补图与建筑场景三视图任务，图片仍经 Codex imagegen 审计入口生成。基础图与三视图分别验收；有图不代表验收通过。

媒体接续：数量以自动生成的 `manifest.json` 和 `STATUS.md` 为准。旧版本和失败请求保留，只有绑定当前SHA的审阅才计为通过。当前新增图片及针对旧主图缺陷的修订记录在 `.audit/adhoc_agents/2026-10-25/xianxia-deep-20261025/`，新 Foundation 请求由现有解析器登记到 `ai_videos/_shared/request_log.md`。

深度审查采用不继承作者会话的独立视角：规则压力测试、社会制度与生命主体、美术与制作使用，以及新采用者的交接测试。只提供当前作品和使用任务；逐项记录质疑、证据回应或修订、复核结论。逐批提交已出图资产，待生成项目不伪装为已审。任何未闭合的重要问题在状态中保留。
