## 三个设计选择（为什么是这么摆的）

**绕身匀速、只一圈、LINEAR 插值。** 缓入缓出会让起步像「被甩出去」，而模型对加速度极敏感——匀速才读得出「它自己在走一条固定轨道」。原稿写「转三圈」是个**频率**请求，必须换成「只走一圈」这种有界写法。**圈速经 follow-up 040 两轮提速到 1.1s／圈**（4.5s → 2.2s → 1.1s，累计 4.09 倍）——两次省下的 3.4s 全部补给前段「飞下来 → 饮酒 → 弃壶」与尾段光柱。1.1s／圈 ＝ 26 帧走完 360°、约 13.8°／帧，远未到走马灯混叠的门槛，方向仍然一眼可辨；但它已越过当初「1.5s／圈 与舞剑无法区分」那条线——**之所以敢越，是因为现在有 previz 视频摆在模型面前，剑与两手的间距是看得见的，不再只靠一句文字**。若成片重现「手持剑舞剑」，圈速是第一个要回退的变量。

**绕行半径 2.1m，不是贴身。** 1.3m 时剑的投影正好叠在人身上，读不出「剑在体外、不在手里」—— 而这正是本参考视频的全部意义。2.1m 时整圈轨迹都在人的剪影之外。

**要手落到具体位置的姿态，反解、不猜角度。** 「两手结印相抱到胸前」第一版是手调肩肘欧拉角，渲出来是「两手抬在胸前但没合拢」——因为肘的 `rot_x` 是在**已被肩 `rot_y` 转过的**局部系里折的，同样的肘角会把手甩到体侧。改成给目标手位、由 `solve_arm()` 数值反解（粗扫 + 三级细化，误差 <1mm）。**纯 FK 不知道躯干在哪**：不加约束时解算器给出的是「上臂横穿胸膛、肘落在身体中线」这种数学完美、人体不可能的解，所以 `_cost()` 里加了两条解剖惩罚（肘必须留在本侧体外、肘不许绕到背后）。

**手建到手指，因为手型就是本镜的防塌缩机制。** 「两手都是道家剑指、掌心蜷握、指缝间没有任何东西」这句话要说明的是**这只手物理上握不住剑柄**——手若只是一块扁板，这条信息在参考视频里等于没有，模型照样把剑塞回手里（前四轮就是这么塌的）。所以掌 + 四指各两节 + 拇指两节，手型做成 `HAND_SWORD_FINGER` / `HAND_GRIP` / `HAND_RELAX` 三组具名姿态按拍驱动：右手一路握着葫芦、脱手后松开，结印起两手转剑指并保持到剑归掌，最后右手重新合拢——全镜唯一一次手真的握在物件上。**拇指的外张是静默姿态，K 帧时必须一起写回**，只写 `rot_x` 会把外张抹掉、拇指与四指并成一排，「拇指压住蜷起的指节」直接消失。

**躯干用收分圆台，不用方块。** 方块躯干读成一块板：肩胸与腰没有分界、上臂整个埋进去，胳膊看不出是独立肢体。改成上下不同径的圆台 + Y 向压扁成「宽而薄」的人体截面，并把肩宽收到躯干半宽之外（±0.21m vs 半宽 0.18m），上臂才露得出来；肘/膝/肩补关节球，否则两段圆柱在弯折处露断口。
**保留双臂、且摆成剑指姿势。** 本可以省掉手臂让 proxy 更简单，但那等于用「没有手」来回避问题。留着左臂横抱胸前、右臂向前平指，才能在画面上**可判地**看到剑的轨道从不经过手。

## 俯角与构图的几何冲突（2026-08-16 实测）

`shot12.md` 原写「约四十五度俯角固定俯视」+「人占画高约七分之一到十分之一」+「庙在画左作边框」。**这三条在几何上不能同时成立**：

- 45° 俯角 + 35mm + 人占画高 1/10 ⇒ 机位高 20.8m、视野只覆盖地面**离机位 11.5m–37.7m 的一条带子**（约 26m 深）；
- 而小庙（世界坐标 `(-21, 19)`）离人 25m 开外，落在带子之外 —— 实测 `world_to_camera_view` 给出庙的 **v=1.163**（>1 即出画外）。

实测四档：

| 俯角 | 庙的 v（>1 出画） | 结果 |
|---|---|---|
| 45° | 1.163 | 庙只剩顶部一条黑边，画面纯空地 |
| 38° | 1.064 | 庙仍出框 |
| 33° | 0.996 | 庙卡在顶边，屋顶被切 |
| **28°** | **0.929** | **庙完整落在左上作边框** ✓ |

用户看四档对比渲染后定 **28°**；`shot12.md` 的俯角表述同步改为「约三十度」。

**follow-up 040 再动一次 → 17°。** 主体放大会让冲突变本加厉：机位靠近后，远处的庙在画面里反而更往上顶。同一组约束在「人占画高约 1/4」下重测：

| 俯角 | 庙的 v（>1 出画） | 结果 |
|---|---|---|
| 20° | 0.985 | 庙被顶出画外 |
| **17°** | **0.926** | **庙在画左，四肢清晰** ✓ |
| 14° | 0.867 | 庙更完整，但俯视感基本没有了 |
| 11° | 0.809 | 近似平视 |

**通用结论（已写进 rule 12.16 §3）**：主体大小 × 俯角 × 背景元素入画，三者互相挤压，**只能定两个**。

## 已知限制

- **「剑绕到背后被身体完全挡住只露出一小截剑尖」在本机位下做不到**：剑与人同在胸高，俯视时相机从斜上方越过肩看得见背后的剑，身体挡不住。这是物理，不是 bug —— 那句遮挡描述只在平视/低机位成立。previz 里 14.3s 剑确实走到正背后（在画面上表现为「升到他头顶后方」），轨迹本身是对的。`shot12.md` 的措辞已改成「剑身被他的肩背挡住一截」。
- **previz 拍不出天上的月亮**：s11 场景里月亮仰角约 18°，任何向下俯的机位都把它压出画外。**这不是要删掉 shot 里的月亮描述的理由** —— Seedream/Seedance 不是物理相机，照样会在俯视构图里给一轮大月，那也正是 s11 锁定描述符 #5 要的。previz 只管运动与走位。
- proxy 是方块与圆柱拼的，没有服装、面部、布料 —— 它只负责传递**运动与空间关系**，长相由角色立绘负责。
- 场景仍是 s11 的低模 previz 精度（树/庙/草为程序化低模）。

## 与 `../whitemodel/` 的关系

`whitemodel/` 是本方案的前身：**纯灰白模、空地面、只演绕身一拍 5.5s**，没有场景。本目录取代它 —— 保留了场景实景与月夜光照，模型同时读得到场景与运动，且覆盖整 20s 全部拍点。`whitemodel/` 保留作历史记录，不再维护。
