# AI Video 全局工作流与覆盖边界

Claude Code 与 Codex 共用此约定。会话结束后，以仓库里的当前源、规格和审计接续，不依赖聊天历史或私有 memory。

## 入口与维护

管理 UI「工作流」是跨剧规则的统一入口：`1_AI Video` 最上面是 `1.0_总览`（follow-up 219，高于单个模块，不占模块编号）：工作流全景（唯一源 `ai_video_workflow_map.json`）与术语表（`ai_video_glossary.json`）；其下依次为六个模块 `1.1_故事创作`、`1.2_影视改编`、`1.3_Prompt编译与出片`、`1.4_剪辑`、`1.5_声音与音乐`、`1.6_成片交付`（后三个待设计，follow-up 218），其余跨剧制作规范、服务规则与公共资源集中在 `1.7_制作、服务与资源`。增删模块、改关卡或交接时同步工作流全景数据。`1_AI Video` 只放创作知识与制作规范文档；一切代码、工具脚本、软件运行与代理设置归 `2_系统与代码`：`2.1_代理与执行设置`、`2.2_管理应用`（`projects/ai_video_management/` 代码与静态默认值）、`2.3_制作工具`（`tools/` 脚本与配置）（follow-up 216）。

唯一目录为 [workflow_catalog.json](workflow_catalog.json)。源正文仍在原位置；UI 当前只读，改进工作流时由 agent 修改对应共用源，再刷新 UI。三级编号：组号在类别内连续，源号在组内从 1 连续，界面按编号排序；源身份是 `scope:path`，改标题不改号；增删或迁移源后运行 `python tools/workflow_catalog.py --fix`，`--check`（Claude Stop hook）与 `test_global_workflow.py` 拦截缺号、乱序和待编号（follow-up 203）。迁入的源排在目标组末尾，新发现的源追加；编号只代表当前目录，不写回历史记录。模块编号与剧内 `2_故事 / 3_影视改编 / 4_prompt编译` 属于不同导航层级。

新增或修改影响 AI Video 的跨剧指南、配置、模板、默认值、编译逻辑或验收工具时，同时维护目录，并运行管理应用的 `test_global_workflow.py`。在「工作流 → AI Video → 工作流覆盖核对」刷新检查：新源待编号、无法解析、分类缺失、已存在的共用文档引用未登记都必须说明或修复。未配置的可选用户设置不是运行失败；检查结果不自动补造配置。

## 应覆盖什么

| 影响面 | 工作流入口 | 生效条件与边界 |
|---|---|---|
| 故事规则、模块输入输出、镜头景别知识 | 三大模块（内容指南在故事创作） | 按本次模块读取；镜头知识用于影视改编设计与比较，不强迫每场使用所有景别 |
| 按任务调用的制作 skill（如人物资产补齐） | 制作、服务与资源 | 按任务选用，不自动加入模块流程 |
| 模型、时长、尺寸、采样、环境覆盖名称、CLI/函数默认值 | 系统与代码（管理应用、制作工具） | 展示静态声明，不执行源码、不读取秘密环境值；实际调用可能被运行环境覆盖 |
| Prompt 模板、角色/声音描述池、编译器规则 | 规则文档在 Prompt 编译；编译器与描述池代码在系统与代码 | 模板正文和编译实现也属于影响源，不能只登记模块级大写常量 |
| AGENTS/CONVENTIONS、Claude/Codex 配置、hooks、规则和共用 skill 入口 | 系统与代码（代理与执行设置） | 用户级设置仅代表当前电脑；两端工具、权限与已加载上下文不保证相同 |
| 调研、资产规则 | 制作、服务与资源及既有资源页 | 资产正文在资源库，目录集中规则和入口；按当前分镜需要引用 |
| 剧/季/集的 README、workflow、世界设定、风格、人物、场景、故事方向和版本 | 既有剧导航与各模块输入 | 属于局部输入，不复制为跨剧规则；系列共享资产也不自动变成所有剧的事实 |
| 外部服务请求与实际参数 | 请求日志与每条的生成记录 | 请求前审计，查询/失败/下载也留痕；「生成永远人点」等授权仍生效 |

## 是什么，不是什么；应该做什么

- 目录是共用源索引，**不是独立的第二份规则库**。编辑原文件并刷新；不在 `.claude/` 复制业务正文。
- 覆盖核对检查目录可读性、连续编号与共用文档中的现存文件引用。它**不证明每个来源当次都加载**，也不保证发现所有隐式 Python 依赖、外部插件或新接入入口。接入者须显式登记影响源并补充检查。
- 静态默认值**不是运行实测参数**。AST 提取不执行表达式；环境变量只列名称。完整模板/编译逻辑以对应源码入口核对。
- 当前源与历史记录（git、`specs/`、`.audit/`）分别查看；历史记录里缺失的系统指令、父代理上下文、模型/采样参数不能由当前配置补证。
- 旧流程（0–7 阶段、rule 规则库、审查 skills 与工具、评测系统）已于 2026-10-11 删除（follow-up 233），历史只在 git、`specs/` 与 `.audit/`；旧剧目录只作数据保留（根目录有 `OBSOLETE.md`），**不是 three-module-v1 的输入**，不从历史恢复旧流程或 legacy BGM。
- 秘密凭据、auth、私有 memory 和 `.env` 正文不进入 UI。外部模型权重、提供方隐藏系统提示、插件内部状态、未保存的会话附加指令属于不可从本仓库穷举的影响，必须以实际会话/请求记录确认。
