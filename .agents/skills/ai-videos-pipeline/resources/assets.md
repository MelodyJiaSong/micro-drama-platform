# 资产

独立管理人物、场景、物件、装备及声音，保留已有真实文件和来源。
环境资产使用background/（完整地点、空间布局与视觉参考，不限于二维底图）；剧情scene是某集中特定时空的一场戏，属于episode→scene→shot并引用环境资产。已迁移《魔兽世界》原资产scenes/为background/，bg编号保留；其他旧剧scenes/继续兼容读取，不批量改名。
资产描述与故事历史分开；已有图片不强迫新故事使用旧人物关系或情节。
长期事实在world_rules.md或对应人物/场景/物品卡维护；需要注明“截至哪集”才成立的位置、伤势、持有物、知识、关系和目标，记录在该集state_changes.md。
按当前分镜需要引用；生成服务、收费审计、人工授权和媒体索引遵共用契约。
独立音频资产默认走 [Suno 音频入口](../modules/sound.md)（环境音、音效、配乐、歌曲等）；声样/对白等先查能力，当前无精确 TTS 或克隆接口时记录缺口，不擅自切本地模型。现有声样或从已有视频提取音轨属于复用，不为默认路由重生成。

## 目录与编号

资产根是剧目录下的 `2_世界观人设/`。编号只追加，分配后不重排、不复用；目录改名只改名字，不改号。一份东西只有一个出处，下游只读、只对账，不回写上游。

| 类 | 目录 | 编号出处 | 编译器读取 |
|---|---|---|---|
| 人物 | `characters/c{N}_{名}/c{N}_{名}.md`（怪物 `m{N}_{名}`）；换装阶段是卡内子目录 `c{N}-{M}_{造型}/` | 卡号按出场顺序手动追加（N 不补零） | 「## Shot prompt 外观」段 |
| 背景 | `background/{大陆}/{区}/bg{N}_{主体}/` 加同名 md；视图与状态变体是子目录 `bg{N}-{M}_{名}/` | `background/registry.toml` | 场次绑定的变体卡里的「Shot prompt 场景」段与图 |
| 道具 | `props/p{N}_{名}/` 加同名 md 与 `asset.toml` | `props/registry.toml`，由 `tools/props_lib.py` 的 `allocate()` 领号，不手填 | 「## Shot prompt 外观」段；锚点图 `{目录名}.png`，没有时回退 `p{N}-1_正面.png` |
| 装备 | `equipment/{大类}/{部位}/e{层级码}_{名}/`，例如 `e5103` 是 5 近战武器 · 51 主手 · 第 03 件 | `equipment/registry.toml`；`item.toml` 是唯一出处；谁穿什么只写 `equipment/loadouts/*.toml` | 换装阶段的三视图 |

| 技能 | 改编自游戏的剧：施法者是固定英雄的放在 `characters/{英雄}/skills/k{键}_{名}/`；按职业共用的放在 `classes/cl{位}_{职业}/skills/k{键}_{名}/`；都加同名 md | 英雄技能键随人物卡号；职业技能 `classes/registry.toml` | 「## Shot prompt 技能」段、峰值图与技能视频（`tools/skill_pack.py`） |

人物与道具的卡目录可再分一层不带键的分组目录（如按阵营：`characters/近卫_sentinel/c65_Axe/`、`props/中立_neutral/p1_极速神符/`），工具与管理 UI 都认（`projects/ai_video_management/libs/common/asset_group.py`）；分组只一层、不带键、不进编号。背景本已可任意嵌套。

## 人物

- **参考文件**：人物本身的放在卡目录的 `views/` 下，`{卡目录名}_front.png`、`_side.png`、`_back.png` 加声样 `{卡目录名}_audio.mp3`；换装阶段的放在自己的子目录里，`{造型键}_front/side/back.png`，声样沿用人物本身的。正侧背三张合成一张三视图 `{卡目录名}_views.png` 或 `{造型键}_views.png`（左正、中侧、右背），源图的 sha 变了，合图即视为过期。编译时每个出场人物上传三视图合图与声样。
- **生成链**：立绘 → 4 秒建立视频 → 抽正、侧、背 → 合图，声样另出。工具与步骤见 [人物资产](../../ai-videos-char-assets/SKILL.md)。缺文件或角色绑错算阻碍，不能用改名冒充某个方向。
- **固定武器**：人物卡可声明 `武器参考: p31,p32`（英文逗号、道具编号）。先制作并逐图验收独立武器锚点，再把它与人物身份图一起用于新人物图。人物立绘、换装三面、建立视频、技能视频资料包和镜头编译自动加入这些图；缺图阻止生成／编译，旧包漏挂则失效。技能峰值图及手工图片请求也必须带同一武器图，武器形制、材质、配色以独立图为准，持有数量与左右手按人物卡／当前状态。天然爪牙不拆成道具，固定机体部件用整机参考。声明只在人物卡维护，道具卡维护形制。
  同款双持可只使用一张单件母版；构件数量按武器结构，人物持有几件按人物卡和镜头，不能从母版画面里的件数推断。
- **颜色对比**：服装与常用背景的色调拉开对比，主角在画面里更容易被注意到，见[注意力引导](../modules/filming-attention.md)。
- **改编自已有作品的人物先看原版图**：人物来自游戏、动画等已有作品时，写外观段和出立绘之前，先把原版模型截图 / 图标 / 动图下载到卡目录 `ref/model/`，`refs.md` 记来源 URL、sha 与「看到了什么」（版权素材只作人眼参考，不上传生成服务）；外观按图写。research 里标 ⚠️（未看图）的外观条目，没看图就不出立绘。来源：dota_yingxiong follow-up 007 / 032（凭记忆写外观，c5–c9 与宙斯颜色、形制全错）。
- **人物卡**：只写看得见的识别特征，不写五官；随镜变化的状态（一身泥、伤、手里拿的东西）写在分镜里，不写进外观段。需要长期区分的状态（例如「一身泥」）可以另立状态变体三视图，用不用由用户定。

## 背景

- **主体与变体**：同一套材质与光算一个主体；时段、天气、季节或损毁改变了外观，就另立状态变体子目录，不在同一张图上改。视图与变体按镜头需要才出，不预先建全套。
- **平面图**：每个背景主体解析到恰好一份场地平面图 `planning/blocks.toml`（块必填 `id`、`h_m`、`src`），overhead 与 previz 都从它取几何（见 [Overhead](../modules/prompts-overhead.md)）。平面图和白模渲染图不进生成参考。
- **背景图只画固定结构**，剧情道具归分镜；主光要有真实光源。

## 道具与装备

- **道具**：跨两镜以上且外观必须一致的剧情道具立卡出图；分镜 `props` 引用它的镜，锚点图会进参考行（见 [参考](../modules/prompts-references.md)）。手持、随身的剧情物件只出正面锚点图。**道具的可见状态每改变一次，画内都要有一个动作驱动它**，不能凭空出现、自己掉落或自己滑开。
- **装备**：prompt 不写游戏里的原名；灰、白、绿档不发光，蓝档以上发品质色光；换装只出正侧背三面图。

## 技能

- **先建技能资产，再拍用到它的镜头**：改编自游戏的剧，技能是一类资产，一个技能一张卡。用户 2026-10-19 定（shengji_zhilu follow-up 108）；DotA 剧最早落地（dota_yingxiong follow-up 003 / 010）。
- **先收原生资料**：原典文字（中英说明、学会等级、施法 / 冷却 / 射程、法术 ID）、游戏图标 `icon/`、客户端数据（动画名、特效模型、挂点、音效）、实机施法截图与动作片段 `ref/`。`ref/refs.md` 记来源 URL、时间点、sha 与「看到了什么」。原生资料和人物原版图一样只给人看、写 prompt 用，不上传生成服务。
- **再定本剧写法**：施法动作分拍、特效、作用结果、声音，以及偏离原典的地方和理由。然后出技能视频（demo），由用户决定出不出、选哪条。
- **出片前先审时间轴（必要流程）**：任何剧、任何角色的技能视频，每次提交（含重出、只改一处的重出）前，先跑 `python tools/skill_pack.py timeline <剧> <技能键>`，把输出的「时间 | 画面」表原样给用户 review；用户在对话里认可后才 `approve`，再 `submit`。时长、位置行或任何分秒行改了，指纹就变，必须重新给用户看表；`submit` 对未审或审后改动的条目直接拒绝。负面词、参考用法等不改时间轴的修改不需重审。AUTONOMOUS 模式也不跳过：没有用户认可就停在表上。来源：用户 2026-10-24（dota_yingxiong follow-up 132 之后）「再做任何角色的技能前，先给我这个时间轴的 table，我们 review 完了再出视频，之后每一个角色，每一个 session 都应该遵循」。
- **技能 demo 的表演与因果**：先写清施法意图、视线目标、武器/手势朝向及身体重心，再按“主动起手 → 可见命中 → 目标反应 → 结果”分拍；不能只让角色静站、亮特效、收势。范围伤害区分主目标/爆心与邻近目标，波及顺序和范围外单位的反应可读；纯范围、增益和被动技能按自身机制设计，不硬加主目标或死亡。
- **射程与特效来源分别锁定**：写清施法者到目标的距离及全程是否保持，不能把“动作有力”拍成远程角色贴脸搏斗。把效果来源高度、生成地点、是否有飞行弹道分别写明；“地面坐标取点”不等于“特效从地面长出”。用户纠正机制时同步技能卡、峰值图与视频参考，旧机制图/旧运动不能继续影响新片。来源：dota_yingxiong follow-up 085；具体距离和空爆方式只属于该技能，不推广为所有法术。
- **空间锚点与时间演化分开写**：同源的爆炸、冰雾等分量共用已指定的作用点，逐项核对爆心/雾心是否落在主目标身体，不能让不同分量各自另起中心。“gradient／渐变”只说明空间浓淡时，不得擅自改成时间上分层慢推；起效同帧、铺开时长、停留及消散另写、另审。来源：dota_yingxiong follow-up 088；同中心和瞬间铺开按具体技能设计采用，不强加给其他机制。
- **致死必须引用受击者的专属动作**：有致死结果时，先检查该角色当前死亡视频与身份、落地终态，将自有死亡视频实际放进资料包参考行，写明仅约束受击后的动作与遗骸，不复制其背景/音轨或提前死亡；不能只在文字里提到参考却漏挂。英雄、小兵及其他单位分别使用自身资产，不互套。未有死亡资产时记录缺口并先补资产或调整本次表现，不拿通用摔倒冒充。原典伤害效果与本镜是否致死分开记录。
- **出片前后逐拍核对**：提交前清除卡片、峰值图用法与视频 prompt 中“不会倒下/不能死亡”等和本次结果冲突的指令；审核实际看瞄准方向、重心和肩肘腕衔接、先命中后反应、范围波及、每只目标至遗骸的一一对应、专属死亡姿势与接地。静态峰值图仅约束特效形制，不能锁死表演；旧片若表演被否定，不再作为新版运动参考。来源：dota_yingxiong follow-up 084（CM 技能1纠偏）；不因此批量重生其他技能。
- **首尾留白（必要）**：所有技能视频开头先留约 0.5–1 秒人物已在场、尚未起手的空镜（敌人可以在动），结尾在一切动作结束后再留至少 1.5–2 秒人物与机位稳定的静止段；时间轴表里把这两段单独列行。用途是剪辑时接转场到下一个技能不显得赶。来源：用户 2026-10-25（dota_yingxiong follow-up 219）「注意做所有视频，视频开头和结尾都留点空隙，这样我之后拼接转场到下一个技能，会更 smooth，不然观众感觉太赶」。
- **镜头怎么用**：用到这个技能的镜头，原样引用卡里的「Shot prompt 技能」段；施法动作、光效以 demo 为准，同一个技能在哪一镜都是同一个样子。
