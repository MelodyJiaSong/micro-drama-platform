# Seedance 写法

调研于 2026-10-10。【官方】＝BytePlus / 火山方舟文档；【实践】＝从业者经验；【未证实】＝来源不一或推断。本剧用 Seedance 2.5（经 Dreamina CLI `multimodal2video`，2026-10-03 实测可用），2.0 的限制仍列出以便对照。出处见审计 `.audit/adhoc_agents/2026-10-10/prompt-references/`。

## 结构与长度

| 要点 | 做法 | 依据 |
|---|---|---|
| 顺序 | 主体 → 动作细节 → 场景与环境 → 光影色调 → 运镜 → 风格 → 画质 → 约束 | 【官方】2.0 进阶公式 |
| 长度 | 2.0 建议不超过约 500 汉字；太长信息分散、只抓重点。不要把整段剧本当 prompt | 【官方】；2.5 的长度建议未找到，本仓库 2.5 实测过约 1000–2000 字可用 |
| 参考已给的不重复 | 参考素材足够准确时，文字只写识别要点 | 【官方，2.5】 |
| 语言 | 中英都可；对白语言统一，不中英混杂（专名除外） | 【官方】 |

## 时间与运镜

| 要点 | 做法 | 依据 |
|---|---|---|
| 时间分段 | 2.5 推荐时间戳，以 1 秒为单位、区间连续（不要 0–3 秒后跳到 5–6 秒）；不要用时间戳控制高频小动作 | 【官方，2.5】；2.0 说精确时间控制不稳定 |
| 一镜一种运镜 | 推、拉、摇、移叠在一起会让画面不稳；冷门术语写「术语 + 解释」 | 【官方】 |
| 可用运镜词 | 推、拉、移、摇、跟、环绕、升降、过肩、俯仰、航拍、一镜到底、希区柯克变焦 | 【官方】1.0 / 2.5 |

## 动作与表演

| 要点 | 做法 | 依据 |
|---|---|---|
| 写到身体部位 | 写幅度、速度、力度；前后动作写清惯性衔接 | 【官方】 |
| 少写高爆发 | 优先慢、轻、连续的小动作；冲刺、翻滚、大跳容易崩 | 【官方】 |
| 情绪外化 | 写「握拳、下颌紧绷」，不写「非常愤怒」；强情绪词换中性词，防发光眼 | 【官方】 |

## 台词与声音

| 要点 | 做法 | 依据 |
|---|---|---|
| 说话人 | 每个说话人写清是谁（参考图绑定 + 识别特征），台词标明谁说 | 【官方】1.5 多人口型 |
| 音色 | 用声样参考时写「用 @音频N 的音色」；台词语气贴近声样更稳 | 【官方】 |
| 多音字 | 生僻或多音字会读错，可换同音常用字 | 【官方】 |
| 去配乐、去字幕 | 「不要背景音乐，只生成环境声与动作声」「不要字幕」；字幕无法 100% 避免；在台词后重复台词里的词容易触发字幕 | 【官方，2.5】 |

## 参考

| 要点 | 做法 | 依据 |
|---|---|---|
| 上限 | 2.5：图 30、视频 10、音频 10、输出 ≤30 秒；2.0：图 9、视频 3（合计 ≤15 秒）、音频 3，输出 4–15 秒。数值唯一维护在 `tools/previz/seedance_ref.py` | 【官方】 |
| 图片宽高比 | 参考图宽高比放在 0.4–2.5 之间、短边不小于 300 像素；怪物三视图 3840×720（约 5.3:1）缩成上传副本后两次「final generation failed」，范围内的镜全部成功。资料包上传副本自动补边成 2:1（`tools/shot_pack.py`） | 【实测】2026-10-11 本仓库：ep1_s2_st5 同一 prompt 未补边两次失败、补边成 1536×768 后一次成功；具体阈值（0.4–2.5、短边 300）沿用方舟接口说明，未逐一试探 |
| 不要用满 | 建议 4–5 个：1–2 张人物图、1 张场景图、1 段运镜视频、1 段音频；越需要精确参考的越靠前 | 【官方】 |
| 定义主体 | `亚伦＝@图片3`，之后每次都用同一个名字 | 【官方】 |
| 人物图 | 头部特写 + 全身照；**不要三视图合图**——会被读成几个人，导致脸漂和双胞胎 | 【官方】FAQ |
| 人数 | 超过 4 人后人数错、重复明显增多；多人场面先分组出图再生成 | 【官方】 |
| 参考里的文字 | 参考素材上的文字最好去掉；不要只靠图上写的名字指定角色 | 【官方，2.5】 |
| 白模 / 3D 预演 | 2.5 正式支持：「参考 @视频1 的运镜和动作」，并把替身映射到人物；有白模也要写清画面内容 | 【官方，2.5】 |
| 白模做法 | 低饱和、单一主光、不建辅助线（轨迹线、坐标轴、相机框会被渲染）；主体不小于画面高度 1/10 并有移动 | 【实践】 |
| 示意图 | 在图上画路径时写「不要显示标记」；俯视站位图直接喂模型没有找到成熟实测 | 【官方，2.5】/【未证实】 |

## 负向与常见失败

Seedance 没有单独的负向参数，约束写进正文；尽量正向描述，否定主要留给字幕与声音。

| 现象 | 修复 | 依据 |
|---|---|---|
| 换脸、身份漂移 | 加大头照，重要素材前置 | 【官方】 |
| 双胞胎、人数错 | 名字后标参考；加防分身句；参考 ≤4 人；不用三视图 | 【官方】 |
| 运镜不听 | 一镜一种运镜，一次只改一个变量 | 【官方】 + 【实践】 |
| 标记、灰模被渲染进画面 | 写清参考只取哪部分；补齐人物与场景参考；去掉辅助线 | 【实践】 |
| 白模不能消除抽卡 | 白模能减少抽卡，仍要多出几条再选 | 【实践】 |

## 本剧怎样落实

编译器的固定行与参考顺序按上表设计，见[Prompt 结构](prompts-structure.md)、[固定规则](prompts-rules.md)、[参考](prompts-references.md)。两处与官方建议不同、是本剧的取舍：人物参考用三视图（用户要求，靠「同一个人的三面」用法句与防分身负面词兜底）；prompt 写到 1100–2800 字（2.0 建议 500 字，本剧用 2.5，上限按 5000 字）。overhead 图上的人名等文字是旧流程的设计，靠「参考用法」交代不入画；出片若出现文字残留，再改为无字版本。
