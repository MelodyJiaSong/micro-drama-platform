# 出片

状态：基础版。把编译好的 prompt 和它的全部参考一起交给生成服务，结果作为该镜头的条保存，供剪辑选条。不能只用文字 prompt 提交。

技能 demo 另按[技能资产的表演、命中因果与专属死亡参考](../resources/assets.md#技能)核对：致死动作视频须实际进入资料包，先命中再死亡；人物不能只静站亮特效。审核须逐拍看施法意图、范围波及与目标到遗骸的对应，不因文件已落盘就认定完成。

## 资料包（每镜标准流程）

每个镜头目录下一个 `资料包/`：prompt 参考的**全部文件各复制一份**（运动参考 overhead 图或 previz 视频、每人三视图、背景图、每人声样），加 `prompt.txt` 与 `manifest.json`。文件名带上传顺序与 key_id，`01_图片1_ep1_s4_st2_overhead.png`、`02_图片2_c14_Brother_Sammuel.png` …；资料包里的 prompt.txt 已把「参考：」行的 `key=>@` 填成 `key=>@图片1`…，与上传顺序一致。资料包是派生缓存（gitignored），整个拿去上传即可。管理 UI 的每镜 prompt 页下方显示资料包：状态（一致 / 等待更新 / 已失效 / 还没建）、每个文件的缩略图或播放器、副本与源文件链接、填好编号的 prompt.txt（follow-up 229）。

| 情况 | 资料包怎样 |
|---|---|
| 刚编译完 / 还没有资料包 | 建：复制全部参考，manifest 记每个源文件的路径与 sha256 |
| 源文件内容变了、prompt 不用变（重画背景图、换声样、重画同一份 overhead） | **更新**：重新复制，manifest 记新指纹 |
| prompt 要重编译才对得上（编译器升版；分镜编译后改过；参考文件不在了；overhead.toml 改了没重画；previz 判定变了） | **失效**：清空，只留 `_失效.md` 写明原因；修好、重新编译后再建 |

```
python tools/shot_pack.py sync <集目录> [镜头key]   # 建 / 更新 / 失效
python tools/shot_pack.py sync --all --quiet         # 全仓（Claude Stop hook 每回合跑）
python tools/shot_pack.py check <集目录>             # 只报告
python tools/shot_pack.py cmd <集目录> <镜头key>     # 资料包最新时打印提交命令
```

## 提交

| 规则 | 说明 |
|---|---|
| 人工审核 | 每次生成由用户决定后才提交（「生成永远人点」） |
| 先记日志再请求 | `cmd` 打印的命令经 `tools/service_call.py` 写请求日志，见[外部服务](../../../references/project/paid_services.md)；上传的是资料包里的文件，`--image / --video / --audio` 按资料包顺序 |
| 模型与分辨率 | 剧 `workflow.json` 的 `prompt.model`（本剧 `seedance2.5`）；草稿用 `prompt.draft_resolution`（默认 **480p**，Seedance 2.5 最低一档），正式条用 `prompt.resolution`（默认 **720p**：用户定，1080p 太耗积分）；超过该模型的参考上限，资料包失效 |
| 两步出片（2026-10-16 用户定，follow-up 265） | ① **草稿**：`python tools/shot_take.py submit <集目录> <镜头key…>`（默认 `--stage draft`）按资料包原样出 480p，便宜、快，落在该镜的 `drafts/`；② 用户在管理 UI 每镜「生成记录」里看草稿，点「通过，可出正式条」或「不通过」（写进该条 `review.md` 的「状态：」行；代理不替用户点）；③ **正式条**：`submit … --stage final`（`--from <条>` 指定草稿，缺省用最新一条通过的）出 720p：资料包全部参考与 prompt 照旧，再把通过的草稿统一成 1280×720、24fps、无声（超过 15 秒切段）作为最后的参考视频追加，「参考：」「参考用法：」行补上它——镜头、走位、表演、节奏照草稿，长相服装仍以三视图为准。`python tools/shot_take.py approved <集目录>` 列出草稿已通过、还没出正式条的镜头。草稿与正式条都要用户决定才提交。用户明确要求跳过草稿时用 `--stage final --no-draft <理由>`：按资料包原样出正式条，理由记进 `generation.json` 的 `no_draft`（follow-up 272）。剧 `workflow.json` 的 `prompt.skip_draft` 写了用户的理由时，该剧不出草稿：不给 `--stage` 就直接按 `--stage final --no-draft <该理由>` 提交（dota_yingxiong 2026-11-02 起，follow-up 335） |
| 镜组（follow-up 331，dota_yingxiong 剧级先试） | 一场里连续几镜可在 filming.json 场下写 `groups: [{"id": "g2", "shots": ["st4", …]}]`，合成一次生成（不跨场、总长 ≤ 模型上限，Seedance 2.5 为 30 秒；没写的镜头照旧一镜一条）。先出**镜组板** `scenes/sN/groups/gN/board.png`（Codex 出图，每镜一格、格内不放字），用户看过才编译出片；编译器给镜组另出一条 prompt（`ep1_s1_g2`：镜组板 → 各镜俯视图 → 人物 / 道具 / 场景 / 声音，正文按「镜头 1…N」分段、镜头之间切换），成员镜头自己的 prompt 不变。资料包、草稿与正式条都在镜组目录，`shot_take.py submit <集目录> ep1_s1_g2`。用户看镜组用预览页 `/group-preview?path=<镜组目录>`（镜组板、出片、镜头分解、prompt、参考）。剪辑时按镜头切点切开；某一镜坏了可以单独按镜头补出。**场故事板**（follow-up 336）：`tools/scene_board.py` 把各镜组板切成每镜一格、配分拍文字和起止秒，从左到右铺成 `scenes/sN/board/`（只给人和代理 review 图、时长、顺序，不上传）；没写镜组的单镜用它的首帧图 `planning/{stN}_first_frame.png` 当一格（首帧图本身照常作为该镜第一张参考上传；chuanyue_yiri follow-up 020），这样整场每一镜出片前都有画面可审；`shot_pack.py sync` 顺带更新，所以改了镜组板它一定跟着变；用户在 `/scene-preview?path=<场目录>`（左侧导航每场第一项「场故事板」）看 |
| 只用可商用的工具 | 条款不明确允许商业用途的服务不用 |
| 结果落盘：每次生成一个条目录 | 正式条 `renders/{YYYYMMDD-HHMMSS}_{submit_id 前 8 位}/`，草稿单独放同一镜头下的 `drafts/{同格式}/`（follow-up 266；管理 UI 与审片串联两处一起读）：视频（文件名带镜头 key）、`generation.json`（submit_id、模型、`stage`（draft / final）、时长、比例、分辨率、积分、参考清单与 sha256；正式条另记 `from_take`）、`prompt.txt`（提交时的原文）、`review.md`（审核）。CLI 出片用 `python tools/shot_take.py poll <集目录> <镜头key> <submit_id> --credits N` 查询、下载并建目录；网页下载的文件经导入也各自进一个目录。一镜可以有多条（follow-up 230） |
| 已有片子的镜头：先分诊再重出 | 出片前审查只审文字和首帧；审完改了分镜，**不等于已有片子要重出**（用户 2026-11-14，chuanyue_yiri follow-up 069：「不是 prompt 变化就一定要重出，只有影响剧情才重出」）。对每个已有片子的镜头，看那条片子本身（逐 2 秒拼图 + 出片审核），分三类：① 剧情 / 台词意思变了（含用户新定的情节）→ 重出；② 片子里亲眼看到的毛病（穿帮、多手、凭空出现消失、拍点没落地、过演、观众会察觉的接不上）→ 重出；③ 只是文字写得更准、片子已经演对或观众察觉不到 → 保留原片，并把分镜改回与片子一致。再看同场一致性：一镜重出会不会和保留的相邻镜对不上。重出清单按 ①② 列给用户，写明每镜的原因和积分，不按 prompt 差异计数 |
| 重试与搁置 | **每个镜头最多重出两次**（用户 2026-11-09，chuanyue_yiri follow-up 049 / 050；取代 2026-10-11「默认 3 轮」）：审核判重出，先按审核建议把便宜的改动做在上游（prompt、分镜、首帧图、负面词），再重出；第二次重出的那条审核仍不满意就**停**，不再出第四条：该镜最新一条的 `review.md` 写「状态：搁置」、每次失败的表现与已试过的改法，剪辑先用几条里最好的一条（或按审核写的可剪区间），并在交付说明里把它列给用户——由用户决定改设计、换镜头、剪辑绕过或接受瑕疵；不为一次随机失败加规则。**同一个毛病之前已经出现过（人数不对、离墙离门太远、站位跑掉、物体凭空消失），这次重出就不要只改文字**：先出一张首帧图（ElevenLabs 出图，参考挂场景图与三视图，文字写死人数和与墙、门的大小关系），自查站位后存成 `planning/{stN}_first_frame.png`，重新编译后它作为第一张参考发出（2026-10-18 EP1 s1 st1：改了三轮文字，门卫仍跑到镜头前、少一名） |

## 将来改为自动

人工审核以后可切换为自动，切换前须具备：每集或每场的积分上限；生成后的自动看片质检；同一镜的重试上限与「原因相同就换方案」；同一场多角度的一致性检查；请求日志照常记录。具备之前保持人工审核。
