# 参考

没有参考，Seedance 保持不住人物、场景、声音的一致。所以每镜都带参考上传：编译器从分镜与资产里找出、排好顺序，写进 prompt 第一段的「参考：」一行与 `prompts.json` 的 `refs`（follow-up 227、228）。

「参考：」一行的格式是 `` 参考：`ep1_s4_st2_overhead=>@`、`c14_Brother_Sammuel=>@`、`c1-1_便服与父亲的锤=>@`、`bg2-6_武厅_兵器架=>@`、`c14_Brother_Sammuel_audio=>@`… ``（follow-up 229）：`=>` 前是有明确 key_id 的参考文件，`@` 是占位，留给后续自动或手动流程换成上传后的编号；正文（参考用法、人物、场景）用同一个 key_id 指认。每镜资料包按同一顺序复制这些文件，资料包里的 prompt.txt 把 `@` 填成 `@图片N` / `@视频N` / `@音频N`。

| 参考 | key_id |
|---|---|
| overhead 图 / previz 视频 | `{镜头key}_overhead` / `{镜头key}_previz` |
| 人物三视图 | 换装阶段目录名 `c1-1_便服与父亲的锤`，没有换装的用人物卡目录名 `c14_Brother_Sammuel` |
| 道具图 | 道具目录名 `p475_葡萄手推车` |
| 背景图 | 环境资产目录名 `bg2-6_武厅_兵器架` |
| 声样 | `{人物卡目录名}_audio`，如 `c1_Aaron_audio` |

## 每镜必有

| 顺序 | 参考 | 从哪来 | 缺了怎样 |
|---|---|---|---|
| 1 | 运动参考：overhead 图（默认）；单独要 previz 的镜换成 previz 视频 | `shots/stN/previz/stN_previz.mp4`；`shots/stN/planning/stN_overhead_ref.png`；由 `planning/previz.json` 决定 | 拒绝编译 |
| 2 | 每个出场人物的三视图（同一个人的正、侧、背） | `cast` 的资产键：`c1-1` → `characters/c1_*/c1-1_*/c1-1_views.png`；`c14` → `characters/c14_*/views/c14_*_views.png` | 拒绝编译 |
| 3 | 每件道具的锚点图（镜头写了 `props` 才有） | `props` 的资产键：`p475` → `props/p475_*/p475_*.png`，只出正面的用 `p475-1_正面.png` | 拒绝编译 |
| 4 | 背景图 | 场的 `background`：`background/**/bgN_*/bgN_*.png`；场次必须绑定环境资产。镜头写了 `background` 时用镜头的（本镜朝另一方向的视角图，follow-up 261）：模型会照场景图的视向取景，反方向的镜要有自己的视角图 | 拒绝编译 |
| 5 | 每个出场人物的声样（不论本镜说不说话） | 人物卡 `views/{卡}_audio.mp3` | 拒绝编译 |

**道具什么时候要挂**（follow-up 231）：跨好几镜反复出现、形制要前后一致的剧情物件（推车、背上的布包、信、武器）。只有文字描述时 Seedance 每镜自由发挥——ep01 s2 第一轮同一辆推车出成带篷货车、敞开木架车，绳结还跑到路边木栅上。特写 / 插入镜里看不到的就不挂，免得模型硬塞进画面。道具卡用剧自己的物件卡生成器写（shengji 的 ep01 补卡生成器即是一例），锚点图按[资产](../resources/assets.md)「出图服务」的引擎出（ElevenLabs → Codex，额度不够才换；不用即梦）。

## 文字也从资产来

| prompt 行 | 来源 | 写法 |
|---|---|---|
| 人物（每人一行） | 人物卡的「## Shot prompt 外观」一段 | 只写看得见的长相、体型、服装、随身物、气质与小动作；不写流程注记、规则编号、路径。随镜变化的（手里拿什么、伤、表情）写在分镜。**不要写与分镜冲突的「哪里空着」**（实测「背都空着」让背上的长包时有时无） |
| 道具（每件一行） | 道具卡的「## Shot prompt 外观」一段 | 只写形制、比例、材质、配色与随身方式；随镜变化的状态（陷进泥里、绳松了、布滑开）写在分镜 |
| 场景 | 背景卡的「## Shot prompt 场景」一段 | 只写地方本身的形制、材质与陈设；不写时段、天气与光，不写人在不在。**不写会被当成道具的小物件**（实测「柱头挂一圈盘好的麻绳」让绳结戏跑到了栅栏上） |

人物名取人物卡标题里的中文名（「Aaron · 亚伦 · …」→ 亚伦），可在剧 `workflow.json` 的 `names` 覆盖。卡里没有这两段就拒绝编译——不从卡里的表格自动摘：表格里夹着规则编号与取证注记，旧流程实测这类注记会被模型当成画面内容。

## 人偶颜色

overhead 的圆点、previz 的小人偶、prompt 里「（@图片1里的蓝色圆点）」用同一张表：剧 `workflow.json` 的 `figure_colors`（人物卡号 → 颜色名）。同一个人在所有镜、所有参考里颜色一样。

| 应该 | 不应该 |
|---|---|
| 主要人物登记固定颜色；从不同框的人可以共用一色 | 每镜临时分配，同一人换镜换色 |
| 不用绿色：previz 背景是绿幕 | 常出场的人用白色：overhead 底色接近白色 |
| 同一镜里颜色不重复（撞色拒绝编译） | 两个常同框的人用同一色 |

## 三视图的取舍

Seedance 官方 FAQ 提醒三视图合图可能被读成几个人；本剧按用户要求用三视图（2026-10-10），「参考用法」固定写明「每张人物三视图是同一个人的正面、侧面、背面，不是三个人」，负面词带「分身、双胞胎、多出来的人」。出片若出现分身，再评估改用单张正面图。

| 应该 | 不应该 |
|---|---|
| 换装阶段用对应的 `c1-N` 三视图，与本集装备阶段一致 | 用人物卡默认三视图拍已经换了装的戏 |
| 一镜人数多时注意参考上限（2.5：图 30、音频 10） | 群戏把每个路人都挂上 |
| 参考换了（重画 overhead、重渲 previz、换三视图或声样、改外观段）就重新编译；资料包会自动更新或失效 | 改了文件却沿用旧资料包 |
