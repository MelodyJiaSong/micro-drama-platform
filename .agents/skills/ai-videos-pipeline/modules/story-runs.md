# 执行与验证：独立创作 run

每次生成或重跑都创建独立 run：**冻结输入 → 创作与审稿 → 记录取舍 → 验证 → 保留候选 → 用户选用草稿**。所有运行时共用，一次只改善一个模块；故事内容标准见[故事内容指南](../../../references/project/story_guidelines.md)。

## 准备与冻结输入

共享配置保存在 `EP/shared/`：`index.json` 登记选定 profile，profile 的 `input.json` 引用同目录 `rules.json`。

- 只组装明确指定版本，冻结为本 run 的 `input.json`；保存完整快照、来源 SHA256、假设与理由。
- 修改规则另建 profile，不改既有 run，不自动取最新规则。
- 旧候选仅在用户明确指定比较或续写时作为输入。

| 输入分组 | 保存内容 |
|---|---|
| 故事设定 | Who 人物、What 事件、Why 动机、When 时间、Where 地点、How 行动因果；篇幅、基调、假设 |
| 背景与事实 | 明确选用的长期事实、此前已确定集的状态 |
| 流程规则 | 选用规则及流程版本、隔离边界、接受标准、其他显式条件 |
| 任务指令 | 完整初始任务及后续追加指令 |
| 运行与模型 | 实际模型、运行身份、可观察采样设置；未知或未记录项标缺项 |

## 创建与运行

创建新 run 及索引；不调用旧编剧系统或生成服务：

```bash
python tools/story_run.py begin --episode-path ai_videos/{剧}/episodes/epNN --input <固定输入JSON>
```

- 不复用旧角色会话、建议或决策；失败也保留旧日志。
- 作者与审稿使用独立上下文，按本次冻结输入执行，不隐式读未选稿。
- 作者任务模板：先列集核心与因果骨架，再写正文；附规则检查证据、新增设定、候选状态变化及未兑现事项。缺项按内容指南裁定。
- 固定流程与输入可核验；创作结果不承诺逐字一致或必然更优。

## 分工与审稿

| 角色 | 职责与可见材料 |
|---|---|
| 主编 | 冻结输入，逐项决策 |
| 独立作者 | 只看冻结输入，写候选故事 |
| 独立审稿 | 只看输入和候选，不看作者提案或主编判断 |
| 实施 agent | 另标实施范围，不计作故事作者 |

- 派发真实任务，保存全文；缺少独立上下文能力标「未审」。实际只有一个 agent 如实说明，不用角色标签冒充多人。
- 每项提议记录**采纳／部分采纳／否决／延后**、决策者、理由、标准、证据及修改结果；没有提议或否决也如实记录。
- 只记录可观察过程与明确理由，不伪造思维链或为展示制造分歧。

## 保存与溯源

每份文件同时标明用途与范围。

| 维度 | 分类 | 内容或含义 |
|---|---|---|
| 用途 | input · 输入 | 冻结设定、资料、规则与指令 |
| 用途 | output · 产出 | 候选故事、状态变化、虚构设定及完整候选数据 |
| 用途 | process · 过程 | 真实任务／回复、工具结果、审稿、意见、取舍、时间线 |
| 范围 | shared · Persistent | 跨 run 复用的配置，不等于已确定事实 |
| 范围 | run · Transient | 本次候选与讨论，不自动跨 run 继承，历史保留 |
| 范围 | canonical · 当前工作区 | 当前草稿或已确定内容；草稿不能标成事实 |

| 保存位置 | 内容 |
|---|---|
| `.audit/adhoc_agents/{date}/{run_id}/` | 原始任务／回复／工具结果与各轮产物；`run.json` 提供 UI 结构 |
| `EP/story_runs.json` | 仅存 run 索引，不复制讨论 |
| 资产库／对应 EP | 长期事实／已确定集状态 |

- 记录实际 agent ID、运行时 ID、职责、模型、起止时间及提议定位；未知项明确标注。
- 每条资料关联实际文件或冻结字段，展示源路径、取用范围、当时内容／指纹与当前源变化。
- 后续配置不得替换历史输入；后续整理或未采用的文件不算当次输入，不补造历史上下文或系统指令。
- UI 只读，提供导航、刷新、复制、下载及对比。EP 导航分共享配置、当前 EP 软链接、runs；run 按索引追加顺序显示，不从 ID 猜顺序。
- 每 run 分输入与规则、产出、过程；每条资料／文档有独立页面、路由、标题及实际文件，对比单独成页，不用聚合页 tab。目录只展开，文档绑定 `run_id` 与视图。
- 逻辑链接定位已保存内容，不依赖操作系统符号链接；修改、保存、确定与编译通过 Claude Code/Codex，UI 不增加这些按钮。

## 验证与比较

按[内容标准 R01–R14](../../../references/project/story_guidelines.md)定位证据、修正文，并单列新增设定、候选状态变化及未兑现事项。

每条记录：`ID | 状态 | 正文定位或输入来源 | 理由 | 修正（若有）`。

| 状态 | 判定 |
|---|---|
| PASS | 有证据满足规则 |
| FAIL | 违反规则 |
| UNVERIFIED | 信息不足，不计作通过 |
| NA | 本次不适用，说明原因 |

- 不用总分抵消失败。硬事实／原作冲突、无来源知识、无条件解围先修正；其他缺项补足或记录限定范围的创作例外，例外不等于满足规则。
- 通过只表示符合本次契约；理解、情感和续看意愿另看真实读者／观片反馈，作者检查不冒充独立观众验收。语义审查仍需判断，当前没有自动剧情机检。

| 对比场景 | 要求 |
|---|---|
| 同规则复跑 | 固定同一 profile，核对 `input_hash` 与规则快照一致，不混入后来更新的规则 |
| 创作任务 | 新独立上下文、相同任务模板，仅路径／运行身份不同；任务全文留痕，不提供对照稿或要求制造差异 |
| 结果比较 | 先列输入／规则异同，再看六问、因果、人物选择、代价、结果和规则证据 |
| 单项规则实验 | 另建 profile，只改一项，保留其余显式输入 |

逐字差异不等于质量；两次同规则结果不能证明某条规则的因果影响。未知模型不能声称型号相同。

## 选用与交接

将用户选中的候选载入草稿：

```bash
python tools/story_run.py promote --episode-path ai_videos/{剧}/episodes/epNN --run-id <run_id>
```

- 完成后默认保留候选；`soft promote` 载入 `story.json` 草稿，**不等于确定版本**。
- `story_selection.json` 保存选用、历史及正文指纹；原 run、长期事实和已确定状态不变。正文另被修改时绑定标为失配。
- 当前 EP 仅为所选 run 真实故事文档的软链接，不复制正文；未选用时不自动挑选。
- 新增人物／规则及状态变化仍为候选。用户确定后才记录对应 EP 的 `state_changes.md`；人工按集序核对已确定前集，不读未来集或把草稿当事实。
- 用户确定故事版本后交给影视改编；上游改变，下游保留并标待更新，不擅自回写上游。
