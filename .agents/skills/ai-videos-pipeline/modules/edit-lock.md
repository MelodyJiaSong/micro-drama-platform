# 锁片

锁片冻结切点与镜头增删，交给声音与音乐、成片交付。锁之后画面再改，下游都要返工。

## 锁片前质检

**【自动】**全部从导出的片子回读，不只看时间线：

- 无空隙、黑帧、闪帧；重跑镜头检测，没有意外的硬切
- 时长、分辨率、帧率（恒定帧率）符合交付规格
- 每段都在登记的可用区间内，没混入首尾坏帧
- 对成片重新对齐，对白与剧本对账；抽点查音画同步
- 切点两侧色差、身份距离、接缝指标在阈值内
- 平均镜长、最长单镜在本剧设定范围内
- 每条进片的条都有绑定 sha 的「通过」审片结论

**【半自动】**轴线与视线翻转、疑似跳切、关键台词有反应承接、开头 3 秒有事件、集尾留问题。

**【人判，独立上下文】**成片是否满足全剧 Vision（剧 README）；评分卡 S5 注意力（观众的眼睛是否落在设计的位置，见[注意力引导](filming-attention.md)）在成片冷看建好后加入；每刀的动机与情绪是否成立；观众会在哪里划走；钩子与爽点强不强；有意违例站不站得住；逐帧找漏掉的伪影。由独立上下文的审稿完成（机制待设计），结论绑定视频 sha256；缺这一步就记未审，不算通过。

## 锁什么

| 冻结项 | 说明 |
|---|---|
| 剪辑决定文件 | 状态改为批准，写明批准人与版本号 |
| 进片的条 | 每条的 sha256 |
| 锁片视频 | sha256，及其质检报告 |

## 锁之后要改

逐个切点登记变更：改哪一刀、为什么、影响哪些下游（对白、音乐落点、字幕、调色），用户批准后出新版本号，旧版本保留。剪辑决定的乐观锁（`base_version`）防止并行会话覆盖已批准的版本。

| 应该 | 不应该 |
|---|---|
| 用户逐条批准后再锁 | 默认选项或等待超时当作批准 |
| 锁片版本与质检、审稿结论绑同一个 sha256 | 审的是旧版、锁的是新版 |
| 锁后改动走变更、出新版本 | 悄悄覆盖已锁的版本 |
