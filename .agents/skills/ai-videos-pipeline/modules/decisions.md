# 决策记录

每次创作都要留下「为什么这样做」：目的、选了什么、放弃了什么、依据哪一条指南。用来审查结果，也用来发现指南哪里不够、哪里该改。决策记录与创作产物一起写、一起更新；产物改了，记录跟着改。

## 对照 Vision

每份决策记录（集级、场级）开头一行「Vision：」写本产物怎样服务剧 README 的全剧 Vision；因与 Vision 冲突而放弃的方案写进被放弃的选项。审查（用户确定版本、出片审核、锁片审稿）的第一问也是「是否满足 Vision」，不满足就不通过，或写明为什么可以例外。没有决策记录的环节（出片审核、之后的剪辑、声音、交付）把这一问写进各自的审核记录。

## 交稿前自检

代理把草稿交给用户确定**之前**，运行 `python tools/audience_check.py <剧目录> <epNN> --module story|filming|render`，缺项先补齐再交；它只查有没有写，不评判好坏，也不拦用户——用户仍可带着缺项确定，缺项写进确定记录。查的格式：

| 文件 | 必须有 |
|---|---|
| 剧 `README.md` | 「## Vision（观众体验）」，其下恰好一行引用（一句话），以及非空的「核心：」行 |
| `decisions/story.md` | 「本集体验：」行、「Vision：」行；「## 体验地图」表（列含 段、体验、事件，每行都填，没有孤儿事件）；「## 观众轨」表（列含 段、知道、在等、处理，处理写兑现 / 延迟 / 颠覆）；「## 目标影响」表（列含 事件、影响，影响写 + 或 −，对照主角的主目标，见[故事结构](story-structure.md)「人物主目标」）；「## 台词逐句」表（列含 对谁、台词、为什么、新信息：每句写这句给对方或观众的新东西，写不出就删这句，见[故事结构](story-structure.md)「每句台词想清楚」）；「## 站位与视线」表（列含 场、谁、在哪、看得见：每场每个有反应的人写站在哪、朝哪、为什么站这，以及他凭什么看见 / 听见让他反应的事，见[故事结构](story-structure.md)「人物都聪明、合逻辑」） |
| `decisions/filming.md` 与每场 `decisions.md` | 「Vision：」行；场级另有非空的「## 观众」小节 |
| `filming.json`（剧 `workflow.json` 声明了 `episode_seconds` 时） | 全集镜头时长之和落在 `[下限, 上限]` 秒内。这是**硬规则**，与上面只查有没有写的项不同：越界不交稿、不确定，先删场删镜 |
| 出片 `review.md`（2026-10-12 起的条） | 「Vision：」项 |

## 独立冷读：台词必问

故事稿的独立冷读（fresh context）除逻辑与 Vision 外，固定问三条，逐句标出：①哪句没有新信息、在重复或换个说法再解释；②哪句不像这个人此刻对这个人会说的话（对陌生人说太多、对亲近的人说得像公文）；③哪句要解释才懂又没人解释。来源：2026-10-17 EP1 s1「My dad's. He wanted me to have it.」两轮冷读都没标出，由用户指出。

## 独立冷读：站位与感知必问

故事稿的独立冷读另做一遍站位与感知，逐场逐人问：①他此刻在哪、朝哪，这个位置符不符合他的职责或目的；②他每个反应（看见、听见、开口、上前、躲）的起因，他凭什么看得见、听得见——中间有没有墙、门、坡、藤架、距离，是不是背对着、压着嗓子；③反过来，他想躲开的人能不能看见他；④他知道的事从哪来（亲眼、别人说、合理推断）；⑤场与场、镜与镜之间谁从哪进、往哪走接不接得上。冷读拿作者写的「站位与视线」表对照故事稿，表里写不出来源的就是问题。影视改编审查与出片审核也问①②：分镜和成片里的站位要和这张表一致。来源：2026-10-18 EP1 s1 门卫写在门洞北口、背对来路，故事稿、分镜、prompt 与四轮出片审查都没发现，由用户指出；补做这一遍后，在 s2–s6 又找出 1 个 blocker、6 个 major。

## 评分卡（确定时由用户打）

用户确定故事或分镜版本时，在对应集级决策记录末尾的「## 评分卡」打分，约 1 分钟；用户的分是准绳，独立评分员的分数与它比对一致率后才作参考（见测试体系提案 §15）。每项 1–5 分，写一句理由；不算总分，不设通过线，只看趋势。

| id | 维度 | 问题 | 1 分 | 5 分 |
|---|---|---|---|---|
| S1 | Vision 与核心契合 | 在给出全剧 Vision 要的体验、并且都建在核心上吗？ | 无关或相反；有段落接不上核心 | 每段都指得出服务 Vision 哪一点、和核心怎样相连 |
| S2 | 观众是主角 | 观众每刻知道什么、在等什么，兑现是时候吗？ | 按人物逻辑或先后平铺，期待没建立 | 期待清楚，兑现前留停顿，兑现 / 延迟 / 颠覆都有意图 |
| S3 | 体验优先 | 事件是为体验挑的吗？ | 件件有事，合不成一种体验 | 事件都对得上体验地图，开场先浓缩本集体验 |
| S4 | 戏剧顺序 | 观众被钩住了吗，交代先行吗？ | 前段堆交代 | 开头就钩住，跳转跟得上 |

S5 注意力只能看成片，等剪辑模块的成片冷看建好后一起做。

```markdown
## 评分卡

| id | 分 | 理由 |
|---|---|---|
| S1 | 4 | 抵达暴风城一段很到位，第三段偏离 |
```

## 写在哪里

| 模块 | 层级 | 文件 | 重点 |
|---|---|---|---|
| 故事创作 | 集 | `episodes/epNN/decisions/story.md` | 开头一句话本集体验及它怎样服务剧级体验；目标影响（每个事件、每个人物对主角主目标是 + 还是 −）；六个问题的答案（多主角各答一遍，见[六个问题](story-questions.md)）；体验地图（每段观众要有的体验）及选中事件的理由；观众轨：每段观众知道什么、在等什么，在哪里兑现或延迟；为什么是这几段；钩子与伏笔怎么放；片种原则怎样套用 |
| 影视改编 | 集 | `episodes/epNN/decisions/filming.md` | 为什么分这几场、场的边界在哪；覆盖预算怎样在各场分配；开场与集尾钩子；跨集连续性 |
| 影视改编 | 场 | `episodes/epNN/scenes/sN/decisions.md` | 这场的目的；覆盖档位与理由；每个镜头为什么存在、为什么是这个顺序 |
| 剪辑、声音与音乐、成片交付 | — | 模块设计后补 | — |

Prompt 编译是固定转换，不写决策记录；每镜 overhead 的摆法理由写在该镜 `overhead.toml` 的 `note`，走位、分拍与光线的取舍写进场级记录；出片若有取舍（重生成、选哪一条）记在剪辑的选条里。

## 场级记录要写什么

| 小节 | 内容 |
|---|---|
| 目的 | 这场在故事里做什么：冲突（谁要什么、被什么挡）、赌注、结束时的变化、情节功能（轻推、段落高潮、幕高潮） |
| 观众 | 进场时观众知道什么、在等什么；这场兑现、延迟还是颠覆这个期待；兑现前留了哪些停顿（见[观众](story-audience.md)） |
| 场的设定 | 地点、时间、环境资产，为什么选它；资产缺口 |
| 覆盖 | 档位（单镜、最少、标准、额外）及理由；考虑过但没选的档位 |
| 动作设计（有打斗、追逐的场） | 完成条件、赌注、每人打法档案、空间与路线、资源、主动权在哪拍翻转、选的结构，见[动作戏](filming-action.md)「先定这场打什么」 |
| 镜头安排 | 每个镜头：作用（主镜头、中景、近景、特写、插入、反应）、覆盖哪些拍点或台词、为什么、依据 |
| 顺序与剪辑意图 | 为什么是这个顺序（例如先主镜头再推近），给剪辑的选择；声音怎样跨镜 |
| 风险与待办 | 生成上的风险；需要上游修改的地方（修改请求） |

## 怎样引用指南

写目录编号、页名和小节，例如「1.2.4 覆盖 · 覆盖多少（标准覆盖）」「1.2.5.4 角度与高度 · 仰拍」。找不到能引用的指南时，写明「无指南，判断依据：……」：这正是要补指南的地方。

| 应该 | 不应该 |
|---|---|
| 写出被放弃的选项和放弃的原因 | 只复述做了什么 |
| 用户的意见翻译成具体哪几场怎么改；遇到「两样都要」，列出二选一和各自代价请用户选 | 照字面改一句，或者两头都塞进去 |
| 依据写到小节，能点进去核对 | 写「按专业惯例」这类无法核对的话 |
| 指南没覆盖、或与指南冲突时明说 | 默默偏离指南 |
| 记录生成限制带来的妥协 | 把妥协写成有意的艺术选择 |
