# 粗剪

把选好的条按分镜接成第一版时间线，看这集的结构站不站得住。

| 阶段 | 是什么 | 审什么 |
|---|---|---|
| 初接（assembly） | 按分镜顺序全部接上，片长偏长 | 每场戏能否成立；缺哪些镜头 |
| 粗剪（rough cut） | 定镜头取舍与顺序，不做细切点、不加音乐 | 结构、信息顺序、开场与集尾 |

## 先音后画

对白时长是确定的：先排对白（实测起止），再让画面去配。每句话落在哪一镜、反应留多久，都从对白时间推出来。无对白的镜头按分镜写的动作与拍点时长排。

## 剪辑决定是数据

| 做法 | 说明 |
|---|---|
| 决定文件是唯一出处 | 格式待设计；每个事件写镜头、条（sha 前缀）、入出点、理由 |
| 入出点只取合法锚点 | 词边界、实测句子起止、镜内切点；不自编时间码 |
| 版本与并发 | 草稿写 `base_version`，防两个会话互相覆盖 |
| 互通 | 需要进 NLE 精修时导出 OpenTimelineIO（DaVinci Resolve 18.5 起原生支持）；CMX3600 EDL 只作兜底，单视频轨、不带元数据 |
| 渲染 | ffmpeg 按帧号重编码切，流复制只能切在关键帧上；出片后用 ffprobe 回读核对帧数 |

## 代理怎样参与

研究系统的做法一致：先把视频变成文字与标注，代理只在有限的操作里选。例如 EditDuet 的剪辑代理只有「检索、加入、移除、交换位置、移动、完成」六个操作，评审代理只能「提意见、渲染」；它最常见的失败是调用不存在的操作、提出做不到的修改（如要求加转场）。

| 应该 | 不应该 |
|---|---|
| 给代理一张封闭的操作菜单 | 让代理自由描述想怎么剪 |
| 每轮出代理片，由独立审稿人看后再改（独立审稿机制待设计） | 代理自剪自评 |
| 粗剪发现缺镜：开单写缺什么、放哪、为什么 | 用别场的条凑数，或拉长现有镜头硬撑 |

## 工具现状

DaVinci Resolve 的 IntelliScript 能把剧本与转写对齐、自动拼时间线，但测试版论坛反馈只采用了约两成指定句子、调过语序的段落会丢；Adobe Firefly Quick Cut 能按剧本或分镜表出第一版，但导不进 Premiere；剪映、火山剧创等「生成与剪辑一体」的产品能自动排出时间线，节奏是否达到可发布水平没有证据。结论：第一版可以交给机器，结构判断仍由人做。详见 [AI 剪辑工具现状](edit-tools.md)。
